## 2. SPY 完整策略实验结果

### 2.1 SPY 最优组合（run_experiments.py 4 阶段输出）

```
档口：波动率动态档口（1-C）     ← SOXL 是固定比例 2%/5%/10%
入场：EMA 过滤（2-B）          ← SOXL 是 NDayConfirm-5
仓位：仅下跌买入（3-C）        ← SOXL 是自适应金字塔
止盈：无止盈（4-0）            ← 相同
```

**SPY 和 SOXL 最优组合完全不同。** 核心原因是 SPY 波动率远小于 SOXL（3 倍杠杆 ETF）：

- SOXL 日波动大，连续 5 天低于 EMA 的机会多 → NDayConfirm-5 有足够的买入次数
- SPY 日波动小，连续 5 天低于 EMA 的机会少 → 需要更宽松的入场条件（EMA 过滤）

### 2.2 止盈策略在 SPY 上全部失败

4-A（偏离度峰值止盈）、4-B（趋势确认止盈）、4-AB（双层止盈）的最大回撤全部飙到 96-100%。

**原因**：止盈的逻辑是"卖出 SPY，把利润转到 SMH"。但当前系统是针对 SPY 做回测，卖掉 SPY 换 SMH 导致持仓偏离了回测标的。这是系统设计上的限制——止盈模块是为 SOXL（卖杠杆 ETF，换非杠杆 SMH）设计的，对纯 SPY 回测不适用。

### 2.3 限价单档口的问题

当前档口设置 `drops=(0.02, 0.05, 0.10)` 是为 SOXL 设计的：

- SOXL 单日跌 5% 很常见（3 倍杠杆），10% 也偶尔发生
- SPY 单日跌 5% 是极端事件（一年 1-2 次），跌 10% 只在股灾时发生

**结论**：如果后续想针对 SPY 优化限价单，需要把档口缩小到 0.5%/1%/2% 级别，否则限价单几乎不会成交。

## 3. 基准 Sharpe 实测数据与解读

### 3.1 完整策略的基准 Sharpe

用 SPY 最优组合（波动率档口 + EMA 过滤 + 仅下跌买入 + 无止盈）跑出的基准 Sharpe：

| 环境 | DCA 年化 | DCA 基准 Sharpe | 买入持有年化 | 买入持有 Sharpe | DCA 赢了？ |
|------|---------|:-:|---------|:-:|:-:|
| 纯熊市 | -3.68% | -0.15 | -18.79% | -0.78 | 大幅胜出 |
| 纯牛市 | +15.96% | 1.12 | +30.05% | 2.10 | 跑输 |
| 熊转牛 | +12.96% | **0.72** | +7.76% | 0.43 | 明显胜出 |
| 牛转熊 | +1.01% | 0.07 | +15.73% | **1.03** | 大幅跑输 |
| 全量(32年) | +4.10% | 0.22 | +10.11% | 0.54 | 跑输 |

### 3.2 数据揭示的 DCA 本质

**DCA 是防守型策略**，在不同市场环境中表现出明确的规律：

```
DCA 胜出的环境：
  纯熊市：买入持有一开始就全仓套牢，DCA 分批买入摊低成本 → 少亏很多
  熊转牛：DCA 在底部持续买入，反弹后成本优势爆发 → 多赚不少

DCA 跑输的环境：
  纯牛市：买入持有第一天全仓买在低位，DCA 分批买入均价越买越高 → 少赚
  牛转熊：买入持有在低位全仓买入并吃到了大部分涨幅，DCA 在高位也在持续买入 → 少赚很多
```

**这不是策略差，是 DCA 的结构特性**——你不可能在第一天就把未来所有的钱都投进去。DCA 的价值在于：你不知道未来是牛市还是熊市，DCA 帮你在不确定中控制风险。

### 3.3 全量 32 年跑输的原因

全量数据（1993-2025）DCA 基准 Sharpe 0.22 vs 买入持有 0.54，看似"策略不行"。但要理解：

```
美股过去 32 年以牛市为主（长牛短熊）
  → 买入持有在第一天全仓买在 1993 年的低位
  → 之后 32 年持续上涨
  → 这是"事后诸葛亮"——你在 1993 年不可能知道未来 32 年是大牛市

DCA 的优势在你"不知道未来走势"时才体现：
  → 如果回测刚好覆盖一个大熊市开头，DCA 会大幅胜出
  → 如果回测刚好覆盖一个大牛市，DCA 会跑输
```

**成本优势比仍然为正（+4.28%）**——说明择时信号确实让你买在了更低的价格，但 DCA 的分批投入结构天然跑不过"第一天全仓"。

## 4. 三种 Sharpe 的计算细节

### 4.1 现有 Sharpe（用于内部排名）

```python
# 分子：年化收益率
total_return = (最终市值 - 总投入) / 总投入          # WR 简单收益率
annualized_return = (1 + total_return) ^ (365/天数) - 1  # 年化

# 分母：DCA 市值波动率
daily_returns[i] = (daily_values[i] - daily_values[i-1]) / daily_values[i-1]
# ↑ 注意：daily_values 包含新买入的股票，买入当天会有虚假波动
annualized_vol = std(daily_returns) × √252

# 现有 Sharpe
sharpe = annualized_return / annualized_vol
```

**特点**：分母被资金注入放大 → 数值偏低（~0.01-0.23）→ 不能跟业界比，但**排名准确**。

### 4.2 加权 Sharpe（综合排名用）

在 5 个环境上各跑一次，得到 5 个 Sharpe，然后加权求和：

```
加权 Sharpe = Sharpe_bear   × 0.15
            + Sharpe_bull   × 0.15
            + Sharpe_bear-bull × 0.35
            + Sharpe_bull-bear × 0.35

all 环境权重 = 0（只做观察，不参与排名）
```

**权重设计逻辑**：

```
bear-bull 和 bull-bear 各占 0.35（合计 0.70）
  → 最重视跨周期表现（先跌后涨 / 先涨后跌）
  → 因为真实投资通常跨越多个牛熊周期

bear 和 bull 各占 0.15（合计 0.30）
  → 纯熊/纯牛是极端环境，权重较低
  → 但不能为零，因为需要确保策略在极端环境下不会太差

all 占 0.00
  → 32 年全量数据跨度太大，趋势变化太多
  → 放进加权会稀释短期环境的区分度
  → 只做参考观察
```

**举例**：

```
NDayConfirm-5 在各环境的 Sharpe：
  bear = -0.02, bull = 0.16, bear-bull = 0.16, bull-bear = 0.03

加权 = (-0.02 × 0.15) + (0.16 × 0.15) + (0.16 × 0.35) + (0.03 × 0.35)
     = -0.003 + 0.024 + 0.056 + 0.0105
     = 0.0876
```

### 4.3 基准 Sharpe（与买入持有对标用）

```python
# 分子：跟现有 Sharpe 一样（DCA 年化收益率）
annualized_return = (1 + total_return) ^ (365/天数) - 1

# 分母：SPY 本身的波动率（不是 DCA 市值波动率）
stock_returns[i] = (close[i] - close[i-1]) / close[i-1]  # SPY 日收益率
annualized_vol = std(stock_returns) × √252

# 基准 Sharpe
benchmark_sharpe = annualized_return / annualized_vol
```

**跟现有 Sharpe 唯一的区别就是分母**：

```
现有 Sharpe 分母 = DCA 市值波动率（被资金注入虚假放大）
基准 Sharpe 分母 = SPY 收盘价波动率（干净的市场波动率）
```

**为什么可以跟买入持有比**：买入持有的 Sharpe 也用 SPY 波动率做分母，分母一样 → 分子大的赢。

## 5. 信号对比阶段该看什么指标

### 5.1 核心结论：成本优势比是第一指标

在信号对比阶段（`compare_signals.py`，标准化执行），**成本优势比是最直接、最有用的指标**。

```
成本优势比 = (期间市场均价 - 平均买入成本) / 期间市场均价

直接回答：你的入场信号有没有让你买在更低的价格？
  +6.14% = 你的平均买入价比市场均价低 6.14%
  -1.03% = 你买贵了 1.03%
```

### 5.2 为什么信号对比阶段 Sharpe 用处不大

三个原因：

**原因一：区分度太低**

标准化执行下，各策略 Sharpe 挤在很窄的区间：

```
无条件每日:    0.13
EMA 过滤:     0.16
NDayConfirm-5: 0.16
RSI 信号:     0.17
AND 组合:     0.16

差异只有 0.01-0.04，很难说谁真的更好
```

成本优势比的区分度大得多：

```
无条件每日:    -0.97%
EMA 过滤:     +4.11%
NDayConfirm-5: +6.14%
RSI 信号:     +7.21%
AND 组合:     +7.50%

差异从 -1% 到 +7.5%，高下立判
```

**原因二：Sharpe 的分母被污染**

现有 Sharpe 的分母（DCA 市值波动率）包含资金注入的虚假波动。虽然所有策略都有同样的问题（排名不受影响），但绝对值没有参考意义。你无法从 0.16 这个数字得出任何有意义的判断。

**原因三：在标准化执行下，Sharpe 是成本优势比的衍生品**

```
标准化执行 = 固定买 1 股 + 无限价单 + 不止盈

策略间的唯一差异 = 买入时机
买入时机好 → 平均买入成本低 → 年化收益高 → Sharpe 高

所以 Sharpe 的排名几乎跟成本优势比一样
→ 看一个就够了
→ 成本优势比更直观、更好解释
```

### 5.3 什么时候 Sharpe 有用

| 阶段 | 主指标 | Sharpe 有用吗 | 原因 |
|------|--------|:-:|------|
| 信号对比 | 成本优势比 | 用处不大 | 变量只有"何时买"，成本优势比直接衡量 |
| 执行优化 | **加权 Sharpe** | **有用** | 变量包含仓位+限价单+止盈，成本优势比无法衡量这些 |
| 与业界对标 | **基准 Sharpe** | **有用** | 判断择时是否跑赢买入持有 |

### 5.4 一个简单的决策指南

```
你在做什么？
  │
  ├─ 比较哪个入场信号更好？
  │   → 看成本优势比（谁买得最便宜）
  │   → 辅助看买入次数（频率是否合理）
  │
  ├─ 优化限价单/仓位/止盈？
  │   → 看加权 Sharpe + Calmar（综合表现）
  │   → 看最大回撤（风险底线）
  │
  └─ 跟买入持有比，择时有没有价值？
      → 看基准 Sharpe vs 买入持有 Sharpe
      → 正面回答"择时到底有没有创造额外价值"
```

## 6. 信号比较的完整操作流程

当你新开发了一个入场指标，需要跟现有信号比较时，按以下流程操作：

### 6.1 流程图

```
新指标开发完毕
  │
  ▼
第 1 步：跑 compare_signals.py，看成本优势比
  │
  ├─ 成本优势比 ≤ 现有最优 → 淘汰（信号不够好）
  │
  └─ 成本优势比 > 现有最优 → 继续 ▼
  │
第 2 步：检查买入次数
  │
  ├─ 太少（某环境 < 20 次）→ 标记"待观察"（数据不够，结论不可靠）
  ├─ 太多（接近无条件每日买入）→ 过滤效果太弱，价值不大
  │
  └─ 合理（各环境 20-150 次）→ 继续 ▼
  │
第 3 步：检查跨环境稳定性
  │
  ├─ 4 个加权环境中，成本优势比都为正 → 稳定可信 ✓
  ├─ 3 正 1 负 → 基本可信，记录薄弱环境
  ├─ 2 正 2 负 → 不稳定，不可靠 ✗
  │
  └─ 稳定 → 继续 ▼
  │
第 4 步（可选）：跑 validate_signal_returns.py，看前瞻收益
  │
  ├─ 20 日涨幅 > 3% 的胜率 ≥ 70% → 可用于期权 ★★★
  ├─ 55-70% → 可尝试期权 ★★
  ├─ 45-55% → 需谨慎 ★
  └─ < 45% → 不建议用于期权 ✗
      （但仍可用于 DCA 买股票，只要成本优势比为正）
```

### 6.2 信号比较 vs 执行优化的区别

**不要把两个阶段的比较标准搞混**：

| 维度 | 信号比较 | 执行优化 |
|------|---------|---------|
| 对应脚本 | `compare_signals.py` | `run_experiments.py` |
| 核心指标 | **成本优势比** | **加权 Sharpe** |
| 辅助指标 | 买入次数、跨环境稳定性 | Calmar（Sharpe 差距 < 0.05 时） |
| 前瞻验证 | `validate_signal_returns.py` | 不需要 |
| 比较的是 | 信号质量（买得便宜不便宜） | 执行效果（限价单+仓位+止盈） |
| Sharpe 有用吗 | 用处不大 | 有用 |

### 6.3 执行优化阶段的排名规则

进入 `run_experiments.py` 阶段后（信号已锁定），排名标准：

```
第 1 步：按加权 Sharpe 排名（各环境 Sharpe × 权重求和）
第 2 步：如果前两名的加权 Sharpe 差距 < 0.05 → 看 Calmar
第 3 步：Calmar 更高的胜出
```

## 7. Sharpe / Calmar 的合格标准

### 7.1 "TWR Sharpe > 1.5"这个标准适用于你吗？

**不适用。** 原因：

```
TWR Sharpe > 1.5 的适用对象：
  → 对冲基金（可做多做空、市场中性策略）
  → 多标的量化组合（有选股 Alpha）
  → 他们有手段把 Sharpe 做到 1.5-3.0

你的策略：
  → 单标的 SPY、只做多、DCA 择时
  → 不可能做到 1.5（SPY 买入持有的 Sharpe 才 0.5-0.7）
  → 而且 TWR Sharpe 对你无效（所有策略都一样）
```

### 7.2 你应该用的标准

**现有 Sharpe（内部排名用）**：

```
这个 Sharpe 的绝对值没有行业参考意义（分母被虚假放大）
只用于策略间排名：数值越大越好
不需要达到任何绝对门槛
```

**基准 Sharpe（与买入持有对标用）**：

```
买入持有 Sharpe 因时期而异（通常 0.4-0.7）

合格：基准 Sharpe > 同期买入持有 Sharpe
  → 说明择时创造了正向价值（跑赢了无脑持有）

良好：基准 Sharpe > 同期买入持有 Sharpe × 1.3
  → 比买入持有好 30% 以上

优秀：基准 Sharpe > 同期买入持有 Sharpe × 1.5
  → 比买入持有好 50% 以上

你的实测数据（熊转牛环境）：
  基准 Sharpe = 0.72，买入持有 = 0.43
  0.72 / 0.43 = 1.67 → 超过 1.5 → 优秀
```

**Calmar**：

```
Calmar = 年化收益率 / 最大回撤

这个标准相对通用，不受 TWR/WR 口径影响：

  > 1.0 = 合格（年化收益 > 最大回撤，收益能覆盖风险）
  > 2.0 = 良好
  > 3.0 = 优秀

但注意：DCA 策略的最大回撤通常比买入持有小很多
（因为分批买入，不会在最高点全仓套牢）
所以 DCA 策略的 Calmar 天然比较好看
```

### 7.3 总结表

| 指标 | 你的场景下的标准 | 说明 |
|------|---------------|------|
| TWR Sharpe > 1.5 | **不适用** | 对冲基金标准，不适用于单标的 DCA |
| 基准 Sharpe | > 同期买入持有 | 合格线；比率越高越好 |
| Calmar | > 1.0 合格，> 2.0 良好，> 3.0 优秀 | 相对通用 |
| 现有 Sharpe | 只看排名，不看绝对值 | 绝对值被系统性压低 |

## 8. 几个容易混淆的概念澄清

### 8.1 WR 和 MWR 不是一回事

```
WR  = (终值 - 总投入) / 总投入
  → 不管每笔钱投了多久
  → 把 1月投的 1万 和 12月投的 1万 同等对待

MWR = 求解年化利率 r，使得所有现金流的终值 = 实际终值
  → 考虑每笔钱的投入时长
  → 1月的 1万投了 12 个月，12月的 1万只投了 1 个月

举例：
  1月投 1万，12月投 1万，年底总市值 2.15万
  WR  = (2.15 - 2.0) / 2.0 = 7.5%
  MWR = 年化 10.0%（因为大部分利润来自早期那笔钱）

WR 低估了真实回报——它假设两笔钱同时投入
MWR 更接近你的实际年化体验
```

### 8.2 策略的波动率 = 股票本身的波动率

```
你持有 SPY，不管在什么价格买的：

  SPY 今天涨 1% → 你的持仓涨 1%
  SPY 今天跌 2% → 你的持仓跌 2%

  不管你是在 $350 买的还是 $450 买的
  买了之后，你承受的日波动 = SPY 的日波动

所以：
  基准 Sharpe 的分母用 SPY 的波动率
  因为这就是你真正承受的风险
```

### 8.3 年化收益率 = 基于 WR 的标准化

```
WR = 总收益率（原始的、不分时间的）
年化收益率 = 把 WR 折算成"每年赚多少"

公式：
  年化收益率 = (1 + WR) ^ (365 / 自然日天数) - 1

举例：
  3 年总共赚了 30% → WR = 30%
  年化 = (1.30) ^ (1/3) - 1 = 9.14%

  6 个月赚了 15% → WR = 15%
  年化 = (1.15) ^ (2) - 1 = 32.2%

年化的作用 = 消除时间长度的影响，让不同时长的回测可以直接比较
本质上仍然基于 WR，只是做了时间维度的标准化
```
