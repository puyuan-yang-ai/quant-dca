## 1. 结论先行

### 1.1 根因

2026-07-29 的收盘价为 729.46，2026-07-30 的收盘价为 741.69。
线上 `v3_n2` 却给出：

| 日期 | 收盘价 | 线上概率 | 是否超过 0.5 |
|---|---:|---:|---:|
| 2026-07-29 | 729.46 | 33.83% | 否 |
| 2026-07-30 | 741.69 | 68.13% | 是 |

检查后没有发现行情错位、日期错位或未来特征泄漏。主要问题来自训练目标：
旧标签把 `SL7` 中心左右固定两根 K 线都标为正例。它表达的是“时间上靠近
底部”，而不是“价格上足够靠近底部”。因此底部后的反弹确认日也被大量标成
正例，模型学习到的自然是“反弹确认形态”，并非纯粹的低价排序。

数据、特征、模型三者的责任可概括为：

1. 标签是主因：优化目标与“尽量低买”不完全一致。
2. 特征是放大器：`rsi_minus_ma`、`confluence_5d`、连续低于 EMA20 天数等
   特征会识别反弹确认。
3. XGBoost 本身没有违反训练目标：它只是在忠实拟合旧标签。

### 1.2 推荐方案

`SL7` 继续只负责生成 Ground Truth 中心，不参与候选日归属。每个 `SL7`
只在其自身定义窗口 `[s-7, s+7]` 内产生价格空间 GT：

```text
premium(t, s) = close(t) / close(s) - 1
label(t) = 1[premium(t, s) <= pct]
```

候选池仍固定为 `NDay2`。若多个 `SL7` 窗口重叠，采用候选日相对各中心的
最小价格溢价。

推荐研究参数为：

```text
sl_n = 7
pct = 0.008
price_lambda = 0.25
signal = NDay2
features = features_v3
model = XGBoost(100 trees, depth 4, learning_rate 0.1)
```

### 1.3 最重要的公平测试结果

公平主尺子不是 AUC，而是“同样买这么多次时，实际多付了多少”。

最终测试期为 2020-01-01 至 2026-04-02，共有 391 个共同 `NDay2` 候选日。
以仓库历史 `v3_n2` OOS 阈值产生的 202 笔购买作为预算，两个模型都从同一
候选池选择 Top-202。每笔购买的多付幅度定义为：

```text
overpay(t) = close(t) / min(close[t-7:t+7]) - 1
```

|---|---:|---:|---:|
| 购买数 | 202 | 202 | 完全相同 |

| 平均多付幅度 | 3.031% | 2.058% | -0.973 个百分点 |

| 多付不超过 0.8% | 23.76% | 33.66% | +9.90 个百分点 |
| 恰为局部最低收盘价 | 13.86% | 16.34% | +2.48 个百分点 |

|---|---:|---:|---|

结论：在“同购买预算、全部买入都计入”的价格尺度下，新方案已经明确优于

### 1.4 是否可以直接上线

可以提交研究 PR，但不建议在这个 PR 中直接替换线上模型，原因是：

1. 真正冻结的线上模型训练期之后，当前只有 7 个已确认标签的 `NDay2`
   候选，样本不足以完成可靠的线上代际比较。
2. 本轮最终测试期在探索过程中已经被观察过，属于较强的历史验证，
   但不能再宣称为从未打开的 pristine holdout。
3. 生产训练链路尚未正式接入 `price_quality` 权重，不能只把研究脚本中的
   模型文件当作可复现生产模型。
4. 新模型的概率阈值仍需校准。不同标签正例率变化后，不能机械沿用 0.5。

最佳实践是先合入本研究 PR，再单独开生产化 PR，完成版本注册、权重接线、
模型导出、阈值校准、最近两个月逐日 replay 和影子运行。

## 2. 原始问题与研究目标

原始业务目标不是预测未来 20 日收益最大，也不是预测“底部确认完成”，而是：

> 在 `NDay2` 初级候选中，让模型尽量把更低、更接近真实局部底部的交易日
> 排在前面。

2026-07-29 与 2026-07-30 的个案暴露了目标错位：

| 特征 | 2026-07-29 | 2026-07-30 |
|---|---:|---:|
| 收盘价 | 729.46 | 741.69 |
| RSI14 | 38.88 | 49.36 |
| EMA20 距离 | -1.78% | -0.12% |
| RSI 相对快线 | -5.68 | +3.21 |
| 距 60 日高点回撤 | -3.72% | -2.10% |
| 连续低于 EMA20 | 5 | 6 |
| confluence_5d | 0 | 1 |

7 月 30 日的价格更高，但反弹确认特征更完整。旧时间标签会奖励这种样本，
所以旧模型给出更高概率并不反常，反常的是训练目标与业务目标不一致。

## 3. 现有两阶段系统

### 3.1 Stage 1：规则候选池

初级候选固定为 `NDay2`：

```text
连续至少 2 个交易日收盘低于 BacktestEngine 口径的 EMA20
```

Stage 1 决定模型“有资格看哪些天”。模型不能找回被 Stage 1 完全过滤掉的
底部，因此必须单独报告 Stage 1 的 Precision、日级 Recall 和事件级 Recall。

### 3.2 Stage 2：机器学习排序

Stage 2 使用 `features_v3` 的 21 个因果特征和 XGBoost，对 Stage 1 候选进行
二次筛选或排序。

本轮保持以下内容不变：

- 候选规则：`NDay2`
- 特征：`ml.features_v3`
- 模型：100 棵树、最大深度 4、学习率 0.1、随机种子 42
- Walk-forward 折数：4
- 最小初始训练集：候选样本的 40%
- Purge/embargo：28 日
- 原有样本唯一性权重：28 日标签窗口重叠的倒数

因此受控实验中唯一的主要变量是标签定义和正例内部价格权重。

## 4. 对 SL7 角色的纠正

研究早期曾使用过“把候选日归属到最近的 SL7 事件”这一表述。这是不准确的，
已被否决。

正确关系是：

1. `SL7` 只从完整 SPY 序列生成 GT 中心。
2. `NDay2` 独立生成模型候选池。
3. 候选日直接读取全市场 GT mask，不做“最近事件归属”。
4. 事件窗口只用于定义 `SL7` 这个 GT 的局部作用域。

也就是说，`SL7` 是标签生成器，不是 Stage 1 过滤器，也不是推理时可见特征。

## 5. 探索过并否决的方案

### 5.1 旧方案：SL7 左右固定 K 根

旧 `v3_n2` 使用：

```text
SL7 中心左右各 2 根交易 K 线全部标正
```

优点是简单，缺点是只看时间距离。一个已经反弹很多的右侧 K 线仍可能是正例，
而一个价格非常接近底部、但超出固定两根的 K 线可能是负例。

### 5.2 无限横向价格扩张

曾尝试过：

```text
只要 close <= 任一 SL7_close * (1 + pct)，就在全历史标正
```

该方案被否决。SPY 长期上行，后期高价 `SL7` 的阈值会吞掉大量更早历史价格。
当 `pct` 稍大时，早期训练折甚至会接近全正例，失去分类意义。

这不是模型问题，而是“价格阈值没有局部作用域”造成的数学问题。

### 5.3 采用方案：SL7 自身定义窗口内的价格 GT

每个 `SL7` 只在 `[s-7, s+7]` 内生效。时间窗口不决定正负，只限定该 GT
事件的自然作用域；窗口内正负完全由价格距离决定。

该设计同时满足：

- `SL7` 仍只用于生成 GT。
- 不会被长期趋势导致的跨年代价格吞噬。
- 相同价格距离得到相同标签含义。
- 能直接生成连续的“离底质量”用于轻微样本重排。

## 6. 空间标签与样本权重

### 6.1 标签

对某个 `SL7` 中心 `s` 和其窗口内交易日 `t`：

```text
premium(t, s) = close(t) / close(s) - 1
label(t) = 1[premium(t, s) <= pct]
```

若多个事件窗口重叠，采用最小 `premium`。

`pct=0.8%` 的含义是：收盘价不高于对应局部最低收盘价的 100.8%。

### 6.2 价格质量

正例内部质量定义为：

```text
quality = clip(1 - premium / pct, 0, 1)
```

- 精确底部：`quality=1`
- 刚好位于阈值边缘：`quality=0`
- 负例：`quality=0`

### 6.3 权重

正例的原始价格权重：

```text
raw_weight = 1 + price_lambda * quality
```

随后在正例内部归一化到均值 1，再乘已有 uniqueness weight：

```text
price_weight_positive /= mean(price_weight_positive)
final_weight = uniqueness_weight * price_weight
```

该归一化的目的不是把整个正类放大，而是只在正类内部轻微排序：

- 越接近底部，权重越大。
- 离底溢价越大，权重越小。
- 正例总体损失规模基本不变。

严格术语建议使用“离底溢价”或“多付幅度”。“超买”在技术分析中常指
overbought，容易与这里的 overpay 混淆。

1. 开发集等预算中位多付幅度最低。

这是一项多目标选择，不是声称 0.8% 在每一个统计量上都排名第一。

## 11. 公平价格尺子

### 11.1 主指标：等预算全部购买

步骤：

1. 只保留两个模型都有 OOS 概率的共同 `NDay2` 候选。
2. 以历史 `v3_n2` fold threshold 实际通过数量作为预算 `K`。
3. 两个模型分别按概率从高到低选 Top-K。
4. 所有被选交易都计入，不因其不是 GT 正例而丢弃。
5. 以候选日前后各 7 根的最低收盘价计算多付幅度。

该指标回答的是：

> 如果两个模型花同样的购买次数，哪个模型实际买得更便宜？

它不依赖 `pct`，因此是不同标签方案之间更公平的业务尺度。

### 11.2 辅助指标：每个 SL7 事件 Top-1

对每个已确认 `SL7` 事件，在 `[s-7, s+7]` 的共同 `NDay2` 候选中，让每个
模型选择概率最高的一天，每个事件只买一次：

```text
event_overpay = close(selected) / close(SL7_center) - 1
```

该指标回答：

> 在同一个已知底部附近，模型更偏好哪一天？

它是事后排序诊断，不是可直接交易的事件识别器，因为实盘当天并不知道未来
哪一天会成为已确认 `SL7`。

### 11.3 为什么“只看命中正例的溢价”不公平

若只统计 `passed & label=1` 的交易，会自动丢掉所有误买，并且 Recall 更高的
模型会纳入更多边缘正例。该指标可能出现“模型抓到更多好交易，中位溢价反而
略高”的假象。

所以它只能做诊断，不能作为最终胜负尺度。

## 20. 已知局限

1. `pct` 同时定义目标宽度，不同 `pct` 的 AP、Precision、Recall 不可直接当成
   同一把尺子。
2. 离底溢价使用未来窗口，仅用于事后评估，绝不能进入推理特征。
3. 事件 Top-1 以已知 `SL7` 为条件，不代表实盘知道事件中心。
4. 最终测试段在探索期间已被观察，不能包装成从未打开的独立测试。
5. 真正 post-deployment 的确认样本只有 7 个。
6. 当前阈值沿用 fold 训练概率中位数或 0.5，只适合横向研究，不是最终交易阈值。
7. 后续已补充下一交易日开盘执行的因果端到端评估；低价排序改善，但经济收益
   尚未改善，详见第 23 节。
8. `features_v3` 使用的 breadth 历史数据仍有项目已知的成分股幸存者偏差。
9. XGBoost 概率未做校准，概率数值不能直接解释为真实发生频率。
10. 研究脚本中的价格权重尚未接入生产 `train_export`。

## 22. 最终判断

空间 GT 解决了本轮最核心的目标错位：它让模型学习“价格离底有多近”，而不是
简单学习“时间离底有几根 K 线”。在同候选、同购买次数、所有买入都计入的
事后价格尺度下，`pct=0.8%, λ=0.25` 已经明确 beat 仓库历史 `v3_n2` OOS。

补充因果端到端评估后，结论需要进一步收窄：新模型在下一开盘实际成交的离底
溢价上仍明显更好，但 20/60/120/252 日收益和现金流 IRR 没有改善。因此当前
足以支持研究代码进入 Draft PR 和影子验证，不足以支持替换线上主模型。

## 23. 因果端到端上线门槛评估

### 23.1 为什么补做

第 11～12 节的等预算 Top-K 是公平的排序诊断，但不是可直接上线的在线规则。
它在测试期结束后才知道总预算 `K`，实盘当天无法预知未来还会出现多少候选。

本节使用 `ml/research/eval_spatial_e2e.py` 补充因果端到端评估：

1. `2005-2019` 只用于放行率校准。
2. `2020-01-01` 至 `2026-04-02` 只做冻结测试。
3. 不使用测试段目标或未来 Top-K 调阈值。
4. 信号在当日收盘后形成，统一顺延到下一交易日开盘成交。
5. 交易费用沿用项目配置，买卖两侧均为 `1%`。
6. 两个模型都从相同 `NDay2` 候选池开始。

旧模型主基线仍为仓库历史 `v3_n2` OOS。新模型主结果使用项目原生规则：
测试概率相对本折训练概率的分位数不低于 `q=0.5`。该规则不读取测试期标签，
并使测试期放行数与旧模型接近。

开发段放行率校准敏感性结果也一并保留。旧模型开发段放行率为 `47.03%`；
空间模型匹配该放行率需要训练分位阈值 `q=0.5433`。

### 23.2 两阶段端到端检测结果

测试期共有 391 个共同 `NDay2` 候选、61 个 `SL7` 事件：

| 指标 | Stage 1 全候选 | 历史 v3_n2 OOS | 空间 GT q=0.5 |
|---|---:|---:|---:|
| 放行/买入信号 | 391 | 202 | 195 |
| 严格空间 GT Precision | 20.72% | 22.77% | **32.82%** |
| Stage 2 候选内 Recall | 100.00% | 56.79% | **79.01%** |
| 全市场 GT 日端到端 Recall | 51.92% | 29.49% | **41.03%** |
| 事件自然窗口覆盖 | 68.85% | 62.30% | **65.57%** |
| 严格 0.8% GT 事件 Recall | 62.30% | 50.82% | **59.02%** |

空间模型比旧模型少放行 7 次，约 `-3.5%`，因此不是靠显著增加交易次数换取
Precision/Recall。就“识别足够靠近底部的 NDay2 候选”而言，端到端改善明显。

### 23.3 下一开盘实际成交价格

离底溢价改为：

```text
execution_overpay =
    next_open / min(open[execution_day-7 : execution_day+7]) - 1
```

| 指标 | 历史 v3_n2 OOS | 空间 GT q=0.5 | 变化 |
|---|---:|---:|---:|
| 实际成交数 | 202 | 195 | -7 |
| 中位离底溢价 | 1.718% | **1.476%** | -0.242 pp |
| 平均离底溢价 | 2.959% | **2.239%** | -0.720 pp |
| P90 离底溢价 | 6.675% | **5.058%** | -1.617 pp |
| 不超过 0.8% | 26.24% | **31.28%** | +5.04 pp |

年份块 bootstrap：

| 差值（新 - 旧） | 点估计 | 95% 区间 | 判断 |
|---|---:|---:|---|
| 中位离底溢价 | -0.242 pp | [-0.965, -0.015] pp | 改善，边界较近 |
| 平均离底溢价 | -0.720 pp | [-1.534, -0.082] pp | 改善 |
| 0.8% 内命中率 | +5.04 pp | [-1.24, +9.69] pp | 方向改善，区间跨 0 |

这说明事后 Top-K 的方向没有消失：改成可在线执行的阈值并顺延到下一开盘后，
新模型仍然买得更靠近局部低点。

### 23.4 经济结果

以下收益均从下一开盘实际成交开始，包含项目配置的双边费用：

| 持有期 | 有效样本（旧/新） | 历史 v3_n2 平均净收益 | 空间 GT 平均净收益 | 差值 95% 区间 |
|---|---:|---:|---:|---:|
| 20 日 | 202 / 195 | -0.09% | -0.42% | [-1.28, +0.56] pp |
| 60 日 | 202 / 195 | 4.48% | 3.54% | [-2.80, +0.68] pp |
| 120 日 | 184 / 179 | 8.12% | 6.94% | [-3.32, +0.70] pp |
| 252 日 | 176 / 169 | 15.97% | 15.32% | [-4.56, +2.01] pp |

所有持有期的点估计都略低于旧模型，但所有年份块区间都跨 0。正确解读是：

- 尚无证据证明空间 GT 改善经济收益。
- 也没有足够证据断言它显著损害长期收益。
- 它更早、更靠左侧地选择低价，减少反弹确认，短期动量自然可能较弱。

按实际现金流计算：

| 指标 | Stage 1 全候选 | 历史 v3_n2 OOS | 空间 GT q=0.5 |
|---|---:|---:|---:|
| Cash-flow XIRR | 14.76% | 14.16% | 14.18% |
| 期末清算收益/总成本 | 48.38% | 43.54% | 42.50% |

新旧 XIRR 相差只有 `+0.03 pp`，属于经济上持平。Stage 1 全买的 XIRR
反而更高，说明当前还没有证明 ML 过滤器产生独立经济 alpha。

项目标准执行层也给出同样方向：

| 指标 | 历史 v3_n2 OOS | 空间 GT q=0.5 |
|---|---:|---:|
| 项目引擎年化收益 | 6.12% | 6.00% |
| 项目引擎 Sharpe | 0.109 | 0.108 |
| 最大回撤 | 12.62% | 13.98% |
| Calmar | 0.485 | 0.429 |

必须注意：当前项目引擎的 DCA Sharpe 会受到持续现金流和市值跳变影响，不是
机构级现金流调整 Sharpe，因此只能用于仓库内同口径诊断，不能拿 `0.108`
直接与市场中性量化策略的 Sharpe 比较。

### 23.5 上线门槛与评级

量化行业不存在统一的“AUC 大于多少即可上线”。更接近机构实践的要求是：

1. 概念与目标定义通过独立审查。
2. 使用真正样本外、控制多重试验的 outcome analysis。
3. 证明扣除成本后的经济价值或至少非劣性。
4. 上线前验证，并在上线后持续监控与再校准。

本项目的内部上线记分卡：

| 维度 | 当前结论 | 评级 | 是否通过主流生产门槛 |
|---|---|---:|---|
| 候选内可分性 | 最终段 AUC 约 0.72，Precision/Recall 明显提高 | B+ | 研究层通过 |
| 因果低价执行 | 下一开盘中位/平均离底溢价改善 | B | 初步通过 |
| 事件稳定性 | 61 个事件，点估计改善但独立事件仍少 | B- | 尚不足 |
| 经济 alpha | XIRR 持平，各持有期未改善 | C | 未通过 |
| 验证独立性 | 最终段已观察，96 组探索，非 pristine holdout | C- | 未通过 |
| GT 权威性 | 尚无锁定人工 Gold Set | C- | 未通过 |
| 生产运维 | 未导出生产版本、未校准概率、未影子监控 | D | 未通过 |

综合评级：

```text
低点预测能力：B / 有效且有实际改善
量化经济价值：C / 尚未证明
生产就绪度：R2.5 / R5（研究候选，适合影子运行，不适合替换主模型）
```

距离可替换线上主模型，至少还差：

1. 锁定人工 Gold Set，独立审核 GT 语义。
2. 做 nested/更高频重训的 walk-forward，记录所有试验并计算 PBO/DSR 或
   其他多重试验校正。
3. 在未参与调参的新时期证明经济非劣，最低要求是 XIRR、最大回撤和长期收益
   不弱于旧模型；若目标是产生 alpha，则还要显著优于旧模型。
4. 影子运行并积累至少 30 个已确认候选做最低 sanity check；达到约 100 个
   相对独立事件后，再做更可靠的代际判断。

### 23.6 外部方法论参照

- Bailey 与 López de Prado 的 Deflated Sharpe Ratio：要求校正多重试验、
  非正态和选择偏差，而不是只看未经修正的回测 Sharpe。
  <https://papers.ssrn.com/sol3/papers.cfm?abstract_id=2460551>
- Bailey 等人的 Probability of Backtest Overfitting：强调普通 holdout 在大量
  策略选择中仍可能失效，应显式评估回测过拟合概率。
  <https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf>
- Harvey、Liu、Zhu 对多重因子发现提出更高统计门槛；其 `t>3` 不能机械套用
  到本模型，但说明 96 组探索后仅凭普通 `p<0.05` 不够。
  <https://www.nber.org/papers/w20592>
- 美联储模型风险管理指引要求上线前验证、独立 challenge、outcome analysis
  与持续监控，而不是给所有模型规定一个统一 AUC/Sharpe 数值。
  <https://www.federalreserve.gov/frrs/guidance/supervisory-guidance-on-model-risk-management.htm>
