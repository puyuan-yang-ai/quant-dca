你正在更新本仓库根目录的 CLAUDE.md。

## 身份

CLAUDE.md 是供未来 AI 智能体使用的高价值操作记忆。不是文档，不是教程。

## 执行步骤

1. 自主探索当前仓库（目录结构、关键源文件、配置文件、scripts），重点识别未来 agent 可能遗漏、误解或违反的知识。可通过 git 历史查看近期哪些文件发生了变动，辅助发现架构变更和目录结构变化。
2. 对照现有 CLAUDE.md，识别过时、缺失、冗余的内容。以当前代码的实际状态为准。
3. 识别 CLAUDE.md 中的"繁文缛节"（详细参数、完整示例组合、具体算法描述、历史背景等），按下列规则拆分：
   - **始终适用的约定/铁律** → `.claude/rules/`（Claude Code 启动时自动加载；只在特定文件类型才相关的，加 `paths:` frontmatter 做 path-scoping，碰到匹配文件时才注入，不占常驻上下文）。
   - **大块按需细则（原理、完整示例、算法）** → `.claude/docs/`，CLAUDE.md 里只留一行**带"何时读"触发词**的指针（如 `改 entry/做信号比较前，读 .claude/docs/strategy-system.md`），而非裸路径 `详见 xxx.md`——因为普通链接不会自动加载，agent 需要知道何时去读。
4. 以新入职高级工程师的视角审视输出：如果他明天加入，这份 CLAUDE.md 是否足以让他避开所有陷阱、快速上手？
5. 输出交付物：
   - CLAUDE.md 完整替换内容
   - 需要创建/更新的 docs/ 文件列表及其完整内容（文件结构自行决定）
   - 在对话中（不落盘）输出变更摘要：列出已删除、已更新、新发现的章节

## 硬约束

- 总行数 ≤ 200 行。超出则按上述规则拆分：始终适用的约定拆到 `.claude/rules/`，大块按需细则拆到 `.claude/docs/` 并用带"何时读"触发词的指针引用。
- 拆分大块细则**禁止用 `@import`（`@path`）语法**——它会把整个文件每次都展开加载进上下文，不省 token（官方明确："helps organization but does not reduce context"）。一律用普通 markdown 指针 + "何时读"触发词。
- 每条规则写成法律（"X 必须 Y"），不是偏好（"建议 X"）。附带一句话理由。
- 用最少文字表达。事实 > 描述，规则 > 解释，约束 > 架构叙述。
- 禁止编造代码库中不存在的内容。所有信息必须来源于仓库实际代码和配置。
- 当代码与已有文档冲突时，以代码为准。
- CLAUDE.md = 仓库宪法 + 导航索引。核心规则、架构骨架、关键命令留在 CLAUDE.md。附着在核心条款上的繁文缛节（详细参数说明、完整用法示例、算法细节、触发条件列表等）拆到 `.claude/docs/`，用带"何时读"触发词的指针引用。
- 拆分判断标准：该内容是"宪法条款"还是"实施细则"？前者留，后者拆。
- 针对未来 AI 智能体进行优化：每条内容都应让 agent 在无人工干预下做出正确决策。

## 必须包含的章节

以下 5 个问题必须在输出中得到回答。推荐章节名：

1. **这是什么？** → `## 目的（Purpose）`——一段话：项目目的 + 技术栈（含版本）。
2. **怎么跑？** → `## 命令（Commands）`——精确的 build/test/run 命令。逐字可粘贴。
3. **代码住哪？** → `## 目录结构（Directory Map）`——关键目录的一行注释式地图（≤15 行）。不要列全部文件。需纳入 `.claude/`（rules/、docs/、skills/）结构，让未来 agent 知道拆出的细则住哪。
4. **什么不能碰？** → `## 关键规则（Critical Rules）`——绝对约束和禁区。
5. **什么是特殊的？** → `## 已知事实（Known Facts）`——本仓库独有的、AI 无法从代码中推断的约定、决策和常见陷阱。

## 信息准入测试

添加任何一行前，问：

> "删掉这条，会不会导致 AI 犯错？"

会 → 加。不会 → 不加。

同时排除：
- 临时性、推测性、历史性内容
- 从 package.json / requirements.txt / tsconfig 等配置文件中一目了然的
- AI 已知的标准语言惯例和框架约定
- 未来计划（放 TODO.md）
- 详细设计（放 `.claude/docs/` 并用带"何时读"触发词的指针引用）
- 可复用的操作流程（SOP、多步工作流）→ 做成 `.claude/skills/`，不要写进 CLAUDE.md 或 docs（skill 只在调用/相关时加载，更省上下文）
- 预期有效期 < 1 个月的内容（放 TODO.md 或 `.claude/docs/`）

## 格式要求

- Markdown，用 ## 分节
- 表格优于长段落
- 代码块仅用于精确命令
- CLAUDE.md **文件内容**里不要输出解释或说明，直接写正文。但变更摘要和拆分文件清单仍需按"执行步骤"第 5 条在对话中输出（此处不冲突：文件里不写解释，对话里给摘要）。
