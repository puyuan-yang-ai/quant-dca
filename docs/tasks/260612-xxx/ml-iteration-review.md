# ML Meta-Labeling 迭代复盘 — 从 MVP 到实战级

> 记录 2026-06-12 整个开发过程的改进路径、关键决策、背后思想、经验教训。
> 目的：为后续迭代提供可复用的方法论。

---

## 0. 起点状态

进入 ML 之前的系统：
- 规则信号：NDay5（连续5天 < EMA20 触发买入）
- 其他辅助规则：VIX 信号、Breadth 背离、RSI 超卖
- 问题：规则信号触发频繁（~1387 次/30年），很多触发点并非好的入场时机
- 需求：**用 ML 过滤掉"不该买"的信号，只保留"在底部区域"的高质量信号**

---

## 1. 第一版：Fixed Horizon 标注（已淘汰）

### 做法
```
label = 1 if close[t+5] > close[t] else 0
```

### 结果
- AUC-ROC: 0.579 | AUC-PR: 0.692
- ML 过滤后胜率: 62.8%，平均收益: +0.63%

### 问题
- "5天后涨没涨"不等于"入场质量好不好"
- 路径不敏感：第2天涨3%但第5天回落→被标记为 LOSS
- 窗口选择任意：为什么5天？没有理论依据

### 教训
> **标注定义了优化目标。如果标注的问题和你真正关心的问题不一致，模型再好也没用。**

---

## 2. 第二版：Triple Barrier + Relative Low（过渡方案）

### 改进思路

**Triple Barrier (de Prado)：**
- 设三道屏障：TP=+2%, SL=-3%, 时间墙=20天
- 先碰哪个就以哪个定标签
- 参数来自 SPY 30年统计（MFE P50=+2.6%, MAE P50=-1.6%）

**Relative Low：**
- label = 1 if entry_price < avg(future 20 days)
- 直接回答"是不是买在了均价以下"

### 结果
| 方法 | AUC-PR | ML平均收益 |
|------|--------|-----------|
| Triple Barrier | 0.741 | +0.53% |
| Relative Low | 0.668 | +1.14% |

### 关键认知
- Triple Barrier 的 AUC-PR 最高 → 标签质量好，模型学得轻松
- Relative Low 的实际收益更高 → 语义最贴合需求
- 但两者都不够直接："你到底在不在底部？"

### 教训
> **"模型学得好"和"标注语义正确"可能冲突。理想情况是两者统一，但如果必须选，先确保标注语义正确，再想办法让模型学好。**

## 3. 第三版：SL7 Proximity 标注（最终方案）

### 核心突破

**从"收益定义"转向"位置定义"：**

之前所有方案都在问"买了之后涨不涨/赚不赚"，但你的真实需求是"我是不是在底部附近买的"。

Swing Low 就是底部的数学定义。直接用它！

### 做法
```python
sl7 = detect_swing_lows(close, dates, N=7)   # 前后各7天的局部最低点
label = 1 if |signal_date - nearest_sl7| <= 3  # 距底3天以内 = 好入场
label = 0 otherwise                             # 离底太远 = 不好
```

### 关键设计决策

**N=7 而不是 N=10：**
- N=10 太严格（30年只有240个底），正标签太少
- N=5 太宽松（490个底），很多是小波动
- N=7 平衡点（349个底），每年约11个，对应真实可交易的底部

**K=3 而不是 K=5：**
- K=3 → 40% 正标签，正负比例健康
- K=5 → 47%，正标签开始"注水"（含了一些不够近的信号）
- K=3 的正标签 20D 胜率 79%，K=5 只有 77%

**前后都算：**
- 信号在底前3天（买早一点）：WR=75%，avg=+3.3%
- 信号在底后3天（底部刚过）：WR=76%，avg=+2.7%
- 恰好同天：WR=89%，avg=+5.5%
- 三种方向都是好入场，没必要只取一种

### 结果
- AUC-ROC: **0.599**（四种方案最高）
- ML 放行 82/276 信号（只保留 30% 最优）
- ML 过滤后平均 20D 收益: **+3.61%**（vs 原始 +2.16%，提升67%）

### 教训
> **把你本来就在用的分析框架（Swing Low）直接编码为 GT，比凭空设计收益率标注更有效。因为你的特征（VIX、breadth、RSI）天然就是为了判断"是否在底部"而设计的，标注和特征的"语义一致性"是模型能学好的关键。**

## 4. GT 设计的核心思想

### 4.1 标注可以使用未来信息

这是最重要的认知突破：

```
GT = 标准答案 = 上帝视角  → 天然需要看未来
特征 = 模型输入 = 当天信息 → 绝对不能偷看
模型 = 从当天信息预测标准答案
```

SL7 需要看后7天才能确认 → 完全合法，因为它是"答案"不是"输入"。
训练数据里所有 SL7 都是已确认的事实。

### 4.2 标注定义了优化目标

```
标注 = "5天后涨"    → 模型学"什么时候5天后会涨"  → 与择时无关
标注 = "在底部附近"  → 模型学"什么时候是底部"      → 正中需求
```

换标注 > 换模型 > 换特征。标注错了，一切白搭。

### 4.3 标注和特征要"语义一致"

你的特征：VIX 高、连续跌天数多、RSI 超卖、breadth 极端低…
这些特征天然描述"市场是否接近底部"。

如果标注问的也是"是否在底部"→ 特征和标注指向同一件事 → 模型能学好。
如果标注问的是"5天后涨不涨"→ 特征和标注指向不同的事 → 模型困惑。

### 4.4 DCA 择时的特殊性

DCA 不是交易：
- 不需要精确到天
- 不怕小幅浮亏
- 买完就长持
- 核心诉求："别买贵了"

所以标注应该直接回答"买贵了没"——而 SL Proximity 就是这个问题的最直接回答。

## 5. 特征工程演进

### v1: 8 个连续特征（初版）
- 纯数值指标：VIX, RSI, breadth, ema_dist 等
- 问题：没有利用系统已有的布尔信号

### v2: 18 个特征（全量）
- 加入 9 个 entry 布尔信号 + 离散指标
- 问题：很多特征无效（safe_haven 恒为0）

### v3: 11 个特征（精简后）
- 移除 safe_haven、vix_spike 等无效特征
- 加入 VIX regime 分级（0/1/2）、vix_above_200ma
- 效果：精简后效果反而更好

### 教训
> **特征不是越多越好。无效特征是噪声，会分散模型注意力。定期做特征重要度分析 + 无效特征移除。**

---

## 6. 模型没有变过

从头到尾都是：
```python
XGBClassifier(n_estimators=100, max_depth=4, learning_rate=0.1)
```

没有调参、没有换模型。所有提升都来自：
1. 改标注方式（最大贡献）
2. 精简特征集（中等贡献）

### 教训
> **在标注和特征没做对之前，调模型参数是浪费时间。"数据 > 特征 > 标注 > 模型"——这是投入产出比的优先级。**

---

## 7. 可视化的价值

每次改完都在交互图表上看实际信号位置：
- 发现 Fixed Horizon 的标签荒谬（好入场被标为 LOSS）
- 发现模型在下跌初期的假阳性
- 发现 SL7 方案的 WIN 信号精准对齐底部

### 教训
> **不要只看 AUC 数字。一定要在价格图上看信号的实际位置。数字可以骗人，眼睛不会。**

## 8. 模型已知局限

| 局限 | 原因 | 可能的改进方向 |
|------|------|--------------|
| 下跌初期假阳性 | "刚开始超卖"和"底部附近"的特征很像 | 加入趋势强度/动量衰减特征 |
| 只看 SPY | 训练和预测都只在 SPY 上 | 多资产验证 |
| 静态阈值 0.5 | 不同市场环境最优阈值不同 | 动态阈值 or 分位数调整 |
| 80/20 单次分割 | 不够严谨 | Walk-forward CV |

## 11. 方法论总结（可复用）

```
1. 先明确"你真正想问模型什么问题"
2. 用那个问题直接定义 GT（不要绕弯子）
3. GT 可以用未来信息，特征不行
4. 确保特征和 GT 有"语义一致性"
5. 先跑统计验证标注的区分力，再动手建模
6. 看图！不要只看数字
7. 标注 > 特征 > 模型（投入产出比）
```
