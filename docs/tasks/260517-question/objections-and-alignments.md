# 期权 + ML 方案对齐清单

> **背景**：用户提出"7-8 成核心持仓 + 1 成仓位做 ML（XGBoost）择时 Bull Spread"的方案。Claude 在前几轮对话中给出多轮质疑和反向建议，整体偏否定。本文档将分散意见结构化，列出**质疑清单**（需用户回应/推翻/接受）和**认同清单**（建议照做），作为后续决策对齐基线。
>
> **覆盖范围**：本次对话全部内容（alpha/beta、Core-Satellite、全天候、CSP/LEAPS、Bull Spread、XGBoost）+ 用户现有量化系统（DCA、Breadth/VIX 入场、止盈、RSI v2 等）。
>
> **颗粒度**：每条 = 标题 + 一句话理由 + 验证/反驳动作（质疑）或下一步动作（认同）。
>
> **使用方式**：用户逐条审视，对每条质疑做出"接受 / 反驳 / 暂不处理"标记，对每条认同决定是否纳入下一步行动计划。

## 一、质疑清单

按严重程度分组：**A. 阻断级**（不解决就别动手）、**B. 重要级**（影响成败但可缓解）、**C. 优化级**（锦上添花）。

### A. 阻断级（必须先解决）

#### A1. Bull Spread 子类型未定义
**理由**：Bull Put Spread 和 Bull Call Spread 在 Theta、Vega、IV 敏感性上**几乎反向**。底部信号 + Bull Call 是错配（高 IV 买入 → IV 崩塌损失），底部信号 + Bull Put 才对位。
**反驳/推翻动作**：在方案文档中明确写出"我用的是 Bull Put Spread / Bull Call Spread / 其他"，并附选择理由（IV 环境、希望的收益曲线形状）。

#### A2. 信号 Alpha ≠ 期权策略 P&L
**理由**：你的"底部识别"信号只解决了期权 P&L 4 维（方向、幅度、时间窗、IV 变化）中的 1 维。剩下 3 维裸跑的话，信号 precision 提升不会线性翻译为 P&L 提升。
**反驳/推翻动作**：用**现规则信号**（不必先上 ML）回测 Bull Put Spread 实际 P&L 一年，跟"直接买等额 SPY"对比 Sharpe / MaxDD / 累计回报。如果跑不过直接买 SPY，方案逻辑就有问题。

#### A3. 未验证 wrapper 就上 ML
**理由**：如果"期权工具"本身就是错配工具，ML 优化等于在错的轨道上加速。先固定信号验证工具选型，再换 ML，是正常工程顺序。
**反驳/推翻动作**：分阶段计划写死 ——「先 wrapper 选型 → 再 ML → 最后实盘」，每阶段独立 Go/No-Go 判据。

### B. 重要级（影响成败但可缓解）

#### B1. XGBoost 训练样本严重不足
**理由**：30 年 SPY ≈ 7500 日，但"真底部事件"（5%+ 跌幅触发抄底信号）≈ 20-50 个。几十个正样本喂树模型 → 过拟合是几乎必然的。
**反驳/推翻动作**：
- 用**严格 walk-forward CV**（不能随机切分）
- 最近 **2-3 年完全留出**作为 out-of-sample 期，研究期不偷看
- 跟现规则 baseline 比 incremental alpha，不跟买入持有比
- 试验特征数量记录在案，警惕多重检验

#### B2. 现规则可能已接近 SPY 可预测性天花板
**理由**：VIX>30 +9.71% 成本优势，是一个**绝对值上限较高**的信号。SPY 是全球流动性最强、被研究最透的标的之一，剩余可挖掘 alpha 大概率小于 1-3%。XGBoost 投入产出比可能不如想象高。
**反驳/推翻动作**：先做一次「现规则 vs 买入持有」全周期 P&L 对比（不止成本优势，要看资金曲线和 Sharpe）。如果现规则相对买入持有的 alpha 已经 < 1%，那 ML 的天花板就是 +1-2%，要权衡投入。

#### B3. Look-ahead Bias 风险（特别是 Breadth）
**理由**：Breadth 数据需要 S&P 500 全成分股**当日收盘**计算。如果信号在盘中触发买入，但实际计算用了收盘数据，就是用未来信息预测过去，回测虚高。
**反驳/推翻动作**：检查 `scripts/fetch_breadth.py` 和 `BreadthEntry` 的数据 pipeline。明确：信号是用 T 日还是 T-1 日的 Breadth？如果用 T 日，是否假定收盘后才执行？回测在哪一天的开盘价成交？

#### B4. 回测缺少历史期权链数据
**理由**：`data/` 目录下只有 VIX 和 K 线，没有 SPY 期权链历史。要做 Bull Spread 回测，需要历史 IV 曲面或至少每月不同行权价的期权价格。用 VIX 作 IV 代理只能近似单腿 ATM 期权。
**反驳/推翻动作**：评估数据源 ——
- 免费近似：用 VIX + Black-Scholes 反推近月 ATM 期权理论价（精度有限，无 skew）
- 付费数据：CBOE DataShop / IVolatility / ORATS（数百-数千美元/年）
- 替代路径：先用近似数据做粗筛，确定方案后再投资精确数据

#### B5. 期权执行成本未建模
**理由**：SPY 期权 bid-ask spread 通常占名义价格 1-5%，远高于股票（< 0.01%）。月度滚动 Bull Spread 的滑点累积起来可以吃掉一年大部分利润。回测如果按 mid 价成交，会显著高估收益。
**反驳/推翻动作**：在期权回测里：
- 买入按 ask 或 mid+30% spread 成交
- 卖出按 bid 或 mid-30% spread 成交
- 每笔加固定佣金（IBKR ~$0.65/contract）
- 跑一遍敏感性分析：滑点假设 ±50% 时 P&L 变化多大

#### B6. 现金 Sleeve 的目标函数未明确
**理由**：之前算过 20% 现金放 SGOV 拖累 ~1%/年，配合 DCA 信号能补偿 ~0.65%/年。**纯收益维度略亏**，但换来更高 Sharpe / 更低 MaxDD / 心理保险。你必须先定义优先级：你的目标是最大化年化回报，还是最大化 Sharpe，还是控制 MaxDD？
**反驳/推翻动作**：在 `experiments_result/` 输出中显式列出三档目标函数下的最优策略：
- 目标 1：最大化年化回报
- 目标 2：最大化 Sharpe
- 目标 3：MaxDD ≤ X% 约束下的最大回报

#### B7. 10% 仓位 → 实际风险敞口可能 > 10%
**理由**：Bull Spread 是"defined risk"，但最大亏损 = 行权价差 - 收到的权利金，通常是收到权利金的 3-5 倍。10% 名义 → 实际最坏损失敞口可能是 30-50%。
**反驳/推翻动作**：明确"10% 仓位"的定义 ——
- 是 10% 的保证金占用？
- 还是 10% 的最坏损失敞口？
- 还是 10% 的名义本金？
建议按**最坏损失敞口**口径，即 10% 是你能承受的"这部分仓位归零"的金额。

### C. 优化级（锦上添花）

#### C1. 止盈策略与新方案的耦合未想清
**理由**：你 Core 部分如果未来引入 Covered Call，会影响 `take_profit` 模块当前的 SPY → SMH 分流逻辑（被 Call 走的 SPY 没法分流）。
**反驳/推翻动作**：先决定 Core 是否引入 CC；引入则在 `src/modules/take_profit.py` 增加 CC 兼容分支。

#### C2. Safe Haven 指标 2022 后失效但代码仍在用
**理由**：`SafeHavenEntry` 在 2022 股债双杀后信号失效（CLAUDE.md 已标注），但仍是可选 Entry 模块。容易在新实验中被误选。
**反驳/推翻动作**：在 `src/modules/entry.py::SafeHavenEntry` 加显式警告注释或弃用标记。

#### C3. 信号比较的"统一执行层"假设可能过强
**理由**：你比较信号时用"市价买 1 股、无限价单、不止盈"消除执行层差异，方法论正确。但最终部署时执行层会扭曲信号实际排名（例如有些信号配合限价档口效果显著放大）。
**反驳/推翻动作**：信号排名出来后，至少在 Top 3 信号上做执行层敏感性分析（不同档口设置 × 不同仓位分布），确认排名稳定。

#### C4. ML 替代规则的"可解释性损失"
**理由**：现规则系统（VIX>30、Breadth<20、Safe Haven>0.02）你能口头解释为什么买。XGBoost 决策是 SHAP 值组合，实盘亏钱时你无法直觉判断是模型坏了还是市场结构变了。
**反驳/推翻动作**：ML 模型必须配 SHAP 解释 + 月度模型稳定性监控（特征重要性是否漂移）。一旦特征重要性结构性变化，暂停模型回到规则。

## 二、认同清单

按维度分组：**现有量化系统的认同点**、**新方案中可推进的部分**、**强烈建议的下一步动作**。

### 现有量化系统的认同点

#### + 机械化执行规则 >> 手感择时
**理由**：你已经把"恐慌时加仓"这件事规则化，避免了人性最大的失败模式（恐慌时割肉、亢奋时追高）。这本身就是稀缺能力。
**下一步动作**：继续维护规则的纪律性，避免在实盘中"破例"。

#### + Breadth / VIX 入场信号有真实统计 edge
**理由**：VIX>30 +9.71%、Breadth<20 +6.63% 的成本优势是显著的（不是噪声）。背后的机制（恐慌溢价 / 流动性溢价）有理论支撑。
**下一步动作**：保持现规则信号作为基线（baseline），任何新方案都要跟它比 incremental alpha。

#### + 多市场环境（bear/bull/bear-bull/bull-bear/all）加权评估
**理由**：单环境过拟合是回测最大陷阱，多环境加权是有效的稳健性检验。
**下一步动作**：新增 ML 模型时仍走同一评估框架，保持可比性。

#### + 统一执行层 → 比较信号质量
**理由**：用最简执行层消除变量，纯比较信号 alpha，方法论正确（见 `compare_signals.py`）。
**下一步动作**：信号筛选阶段继续这个做法。

#### + 可组合策略架构（4 模块解耦）
**理由**：Tiers / Entry / Position / TakeProfit 解耦让消融实验和 4 阶段优化成为可能，工程架构上是好设计。
**下一步动作**：未来 ML 信号可以作为新的 Entry 子类接入，不破坏现有架构。

#### + Oracle 基准（Swing Low 均价）提供客观参照
**理由**：日线 +15.35% / 周线 +18.65% 的极值给了所有策略一个统一的"完美 vs 实际"比例尺。
**下一步动作**：ML 信号也用同一 Oracle 参照衡量极值利用率。

### 新方案中可推进的部分

#### + 核心 + 卫星仓位分配（7-8 成 + 1 成）
**理由**：分配本身合理。比"一把梭哈躺平"（无 alpha 探索）和"全现金等机会"（机会成本巨大）都更优。
**下一步动作**：把 7-8 成的 Core 明确分散（不只是 SPY，加 QQQ / 大科技 / 国际敞口）。

#### + 10% 投机仓位上限克制
**理由**：即使全部归零也只是 -10%，可恢复。比新手常见的 30-50% 投机仓位安全得多。
**下一步动作**：明确"10% 是按最坏损失敞口而不是名义本金"的口径（见 B7）。

#### + 用 ML 升级现规则是合理方向
**理由**：XGBoost 在非线性交互上理论优于硬编码规则（多指标组合的非线性边界）。即使最终增量小，做这个尝试是值得的，可以验证规则是否已是局部最优。
**下一步动作**：按 B1 的红线设计实验，把 ML 当作"规则 baseline 的可能增强"，不是替代。

#### + 追求 alpha 的动机正确
**理由**：你不满足于纯 Beta，主动寻找 alpha 来源，方向上完全对。绝大多数散户连 Beta 都拿不全，你已经在更高层次思考。
**下一步动作**：保持这个思考强度，但每次新想法都强制走"假设 → 回测 → 实盘小仓"三步验证。

#### + 量化 + 实战结合的路径
**理由**：不靠手感，用回测做决策依据，这是从业余到专业的关键分水岭。
**下一步动作**：把每一个实盘决策都对应一个回测结论，建立"决策 → 回测依据"的可追溯链路。

### 强烈建议的下一步动作（按优先级）

#### → 第 1 步：固定信号，做 Wrapper 选型实验
**理由**：在加 ML 之前，先用**现规则信号**回测 5 个 wrapper：直接买 SPY / Bull Put Spread / Bull Call Spread / LEAPS Call / Cash-Secured Put。
**下一步动作**：
- 时间预算：1 个月
- 输出：5 个 wrapper 在 bear/bull/bear-bull/bull-bear/all 五环境下的 Sharpe / MaxDD / 累计回报对比表
- Go/No-Go 判据：至少一个 wrapper 跑赢直接买 SPY > 0.2 Sharpe，否则放弃期权方向

#### → 第 2 步：CSP 作为 Cash Sleeve 利息化
**理由**：Cash-Secured Put 把"等待中的现金"利息化，不增加新风险维度（你反正打算抄底）。这是几乎没有缺点的改进。
**下一步动作**：在第 1 步的实验里把 CSP 作为对照组。

#### → 第 3 步：选定最优 Wrapper 后再上 XGBoost
**理由**：模型替换信号是独立变量，跟 wrapper 选型不要同时变。
**下一步动作**：
- 时间预算：2-3 个月
- 输出：ML 信号 + 最优 wrapper 的 incremental alpha vs 规则信号 + 同 wrapper
- Go/No-Go 判据：out-of-sample（最近 2-3 年）incremental Sharpe > 0.1，否则坚持规则

#### → 第 4 步：实盘小仓位验证
**理由**：回测和实盘有 gap，小仓先验证执行细节和心理承受。
**下一步动作**：
- 起始仓位：2-3%（不是 10%）
- 跑 6-12 个月，每月对比实盘 vs 回测预期
- 偏差 < 20% 才考虑放大到 10%

## 附：本对话产生的关键结论汇总（一句话版）

- **概念层**：你对 alpha/beta 的理解大体正确；alpha 至少三类（横截面、时序、结构性卖保险）；纯 Beta 已经稀缺。
- **配置层**：Core + Cash Sleeve + 投机 = 散户最优组合；CSP 是 Cash Sleeve 的利息化正解；LEAPS 比 Bull Spread 更匹配底部方向信号。
- **量化层**：你现 DCA 系统已是 alpha；XGBoost 增量大概率小但值得尝试；wrapper 选型必须在 ML 之前。
- **执行层**：分阶段验证，不要同时改多个变量；小仓位实盘 6-12 个月再放大。
