## 1. 你现在面对的核心问题

你有两个"策略"：

- **DCA best 策略**：连续 5 天低于 EMA 才买入（NDayConfirmEntry），经过实验调参已是最优
- **RSI v2 指标**：通过 B/B+/B++ 信号识别底部买点

你直觉上觉得 RSI 更准，但无法量化比较，因为：
- DCA 策略是一个完整的交易系统（包含信号 + 执行）
- RSI 目前只是一个指标（只有信号，没有执行）

**就像让一个穿着跑鞋的运动员和一个光着脚的运动员比赛——不公平，因为条件不一样。**

## 2. 量化策略的两个层面

任何一个完整的量化策略都可以拆成两层：

### 2.1 信号层（Signal）— "什么时候买/卖"

信号层负责回答：**今天要不要操作？**

| 信号类型 | 示例 | 回答的问题 |
|---------|------|----------|
| 无条件 | 每天都买 | "每天都操作" |
| EMA 过滤 | 连续 N 天低于 EMA 才买 | "趋势弱了才操作" |
| RSI 信号 | 出现 B/B+/B++ 才买 | "超卖了才操作" |
| 组合信号 | EMA 过滤 + RSI 信号 | "趋势弱 + 超卖才操作" |

### 2.2 执行层（Execution）— "买多少、怎么买"

执行层负责回答：**决定买了之后，具体怎么操作？**

| 执行环节 | 示例 | 回答的问题 |
|---------|------|----------|
| 价格档位（Tiers） | 开盘价、跌 2%、跌 5%、跌 10% | "在什么价格挂单" |
| 仓位分配（Position） | 市价 0.7 股，限价逐档递减 | "每档买多少" |
| 止盈退出（TakeProfit） | 偏离 EMA 超过 X% 时卖出 | "什么时候卖" |

### 2.3 关键认知

```
完整策略 = 信号层 + 执行层

信号层决定"时机"（何时进场）
执行层决定"力度"（进多少、怎么退）

两者是独立的，可以自由组合。
```

**类比**：信号层是"什么时候去钓鱼"（天气、潮汐、季节），执行层是"用什么鱼竿、鱼线、鱼饵"。同一套钓具，不同时机去，结果完全不同；同一个时机，不同钓具，效率也不同。

## 4. 公平比较的方法

### 4.1 控制变量法

科学实验的基本原则：**一次只改一个变量**。

| 变量 | best 策略 | RSI 策略 | 是否相同 |
|------|----------|---------|---------|
| Entry（信号） | NDayConfirm(5) | RSISignalEntry | **不同**（这是要比的） |
| Tiers（档位） | FixedTiers | FixedTiers | 相同 |
| Position（仓位） | AdaptivePyramid | AdaptivePyramid | 相同 |
| TakeProfit（止盈） | NoTakeProfit | NoTakeProfit | 相同 |
| 数据 | SOXL | SOXL | 相同 |
| 手续费 | 1% | 1% | 相同 |
| 日期范围 | 5 个环境 | 5 个环境 | 相同 |

### 4.2 评价指标

| 指标 | 含义 | 越高/越低越好 |
|------|------|-------------|
| **年化收益率** | 每年平均赚多少 | 越高越好 |
| **最大回撤** | 最惨的时候亏了多少 | 越低越好 |
| **Sharpe Ratio** | 承担单位风险获得的超额收益 | 越高越好（> 1 算好） |
| **Calmar Ratio** | 年化收益 / 最大回撤 | 越高越好 |
| **胜率** | 有信号的日子里，买入后盈利的比例 | 越高越好 |
| **盈亏比** | 平均盈利 / 平均亏损 | 越高越好（> 1.5 算好） |

**最重要的两个**：
- **Sharpe Ratio**：综合衡量"收益/风险"
- **最大回撤**：衡量"最坏情况能亏多少"

### 4.3 多环境测试

不能只在一个时间段比较，因为某个策略可能恰好"适合"那个阶段。必须在多个不同的市场环境下都跑一遍：

| 环境 | 时间段 | 特点 | 为什么要测 |
|------|--------|------|----------|
| bear | 2022 | 纯下跌 | 测试抗跌能力 |
| bull | 2022.10-2024.07 | 纯上涨 | 测试牛市中的表现 |
| bear-bull | 2022-2024.07 | 先跌后涨 | 测试能否在转折点抓住机会 |
| bull-bear | 2022.10-2025.04 | 先涨后跌 | 测试能否在顶部控制风险 |
| all | 2010-2025 | 全量 | 长期综合表现 |

**最终评判**：用加权综合评分，不同环境给不同权重（你的实验框架已经实现了这个）。

## 6. 标准化执行层：快速迭代的基础

### 6.1 为什么需要标准化执行

如果每换一个信号策略都要重新调优执行层参数（Tiers/Position/TakeProfit），那么：

```
10 个信号 × 每个调 4 阶段执行参数 = 极其耗时
10 个信号 × 统一简单执行对比 = 几分钟搞定 → 找到最好的 1 个 → 只对它精细调优
```

**先用最简执行快速筛信号，赢了再精细调优执行。** 这是量化研究的标准做法，叫"标准化执行"或"信号 alpha 测试"。

### 6.2 标准化执行配置

所有信号策略统一使用以下最简执行层：

```python
# 标准化执行层 — 用于所有信号的公平比较
COMPARE_TIERS    = FixedTiers(drops=())                    # 不挂限价单，只有市价单
COMPARE_POSITION = FixedPyramid(market_shares=1)           # 每次固定买 1 股
COMPARE_TP       = NoTakeProfit()                          # 不止盈
```

| 执行模块 | 配置 | 说明 |
|---------|------|------|
| Tiers | `drops=()` | 无限价单，只有市价单（开盘价成交） |
| Position | `market_shares=1` | 有信号就买 1 股，无信号不买 |
| TakeProfit | `NoTakeProfit` | 买了就持有，不卖 |

**为什么这样设计**：

- **无限价单**：避免限价单成交与否的随机性干扰比较
- **固定股数**：消除仓位策略差异，纯粹比较"在什么时间点买入"
- **不止盈**：消除卖出时机差异，纯粹比较"买入时机的质量"

### 6.3 使用方式

```bash
# 信号比较脚本（待实现）
python scripts/compare_signals.py

# 输出示例：
# ┌──────────────────┬─────────┬────────┬──────────┬──────────┐
# │ 信号策略          │ 年化收益 │ Sharpe │ 最大回撤  │ 综合评分  │
# ├──────────────────┼─────────┼────────┼──────────┼──────────┤
# │ UnconditionalEntry│ +12.3%  │  0.85  │  -45.2%  │   0.62   │
# │ NDayConfirm(5)   │ +18.7%  │  1.23  │  -32.1%  │   0.88   │
# │ RSISignalEntry   │ +21.2%  │  1.45  │  -28.5%  │   0.95   │  ← winner
# │ EMA+RSI融合       │ +19.8%  │  1.38  │  -25.3%  │   0.91   │
```

## 7. 常见问题

### Q1：为什么不能直接比较"DCA 总收益"和"RSI 总收益"？

因为 DCA 每天都在买，RSI 只在有信号时才买。DCA 买入次数远多于 RSI，投入的本金也多得多。用总收益比没有意义，必须用**收益率**（考虑投入本金的比例回报）。

### Q2：RSI 信号少，是不是说明它更"挑"？

是的。RSI 信号少意味着它更加"精选"买入时机。但信号少也有代价——可能错过一些好机会（在牛市中不够积极）。这就是为什么需要在多个环境下测试：
- 在熊市：信号少是优势（避免频繁在下跌中买入）
- 在牛市：信号少可能是劣势（错过了上涨机会）

### Q3："融合"策略一定比单一策略好吗？

不一定。融合 = 更严格的过滤 = 更少的信号。

```
EMA filter:  在下跌中买 → 信号 100 次
RSI signal:  在超卖时买 → 信号 50 次
EMA + RSI:   下跌 + 超卖  → 信号 30 次

信号更少 → 更精准 → 但可能错过更多机会
```

最终取决于"精准度提升"是否能补偿"信号数量减少"的损失。**只有回测数据能告诉你答案。**

### Q4：怎么判断一个策略是真的好，还是"过拟合"？

**过拟合**：策略在历史数据上表现很好，但在新数据上失效。常见原因：

- 参数调得太精细（恰好适配过去的数据）
- 只在一个时间段测试（恰好那个阶段有效）

**防止过拟合的方法**：

1. **多环境测试**：在 5 个不同的市场环境下都能表现良好
2. **参数鲁棒性**：参数微调（比如 RSI 周期从 14 改到 12 或 16）结果不应剧变
3. **样本外测试**：用过去的数据调参，用最近的数据验证
4. **简单优先**：参数越少的策略越不容易过拟合（这也是为什么你的 RSI v2 把背离参数从 5 个减到 1 个）

### Q5：我应该追求高收益还是低回撤？

取决于你的风险偏好。但对于 DCA 长期投资：

```
高收益 + 高回撤 = 坐过山车，心理压力大，容易在底部恐慌卖出
低收益 + 低回撤 = 太保守，跑不赢通胀
适中收益 + 可控回撤 = 能拿得住的策略才是好策略

Sharpe Ratio 平衡了这两者：
  Sharpe > 1.0 → 不错
  Sharpe > 1.5 → 很好
  Sharpe > 2.0 → 优秀
```

### Q6：Baseline 需要多强才够？

没有绝对标准，关键是**比"无脑定投"更好**。

```
无脑定投（每天固定买）→ 最基础的 Baseline
你的 best 策略 → 经过调参的 Baseline
新策略 → 挑战者

只要新策略在大多数环境下的 Sharpe 和最大回撤优于 Baseline，
就可以升级为新的 Baseline。
```

### Q7：信号层和执行层都需要各自调优吗？

**是的，两者独立优化，最终组合。**

```
信号层优化 = 找"什么时候买"的最优方案
  → 比较不同 Entry 模块（EMA过滤 vs RSI信号 vs 组合）
  → 评价标准：择时准确度（信号出现后的收益率）

执行层优化 = 找"怎么买"的最优方案
  → 比较不同 Tiers/Position/TakeProfit 组合
  → 评价标准：相同信号下的最终收益率和回撤
```

你的 4 阶段实验框架做的就是执行层逐步优化：

```
Stage 1: 锁定最优 Tiers（档位怎么设）
Stage 2: 锁定最优 Entry（信号怎么判断） ← 这里其实混了信号层
Stage 3: 锁定最优 Position（仓位怎么分）
Stage 4: 锁定最优 TakeProfit（止盈怎么做）
```

### Q8：换了信号层，执行层需要重新调优吗？

**需要。** 不同的信号有不同的"出手节奏"，最优执行参数会跟着变。

```
NDayConfirmEntry（出手频繁，几乎每次回调都买）：
  → 每次买少一点（分散投入）
  → AdaptivePyramid 小仓位效果好
  → 因为买的次数多，靠次数摊薄成本

RSISignalEntry（出手精选，只在超卖时买）：
  → 每次可以买多一点（信号精准，要把握住）
  → 可能更大的仓位效果更好
  → 因为买的次数少，靠单次精准获利
```

**类比**：同一个猎人换了不同的猎场（信号变了），枪和子弹（执行）也需要调整——在丛林里用散弹枪，在草原上用步枪。

### Q9：实操上应该先比信号还是先调执行？

**分两步走，先粗后细。**

```
═══════════════════════════════════════════════
  第一步：公平比较信号质量（执行层不动）
═══════════════════════════════════════════════

  策略A: Entry = NDayConfirm  + 执行层 = best（不动）
  策略B: Entry = RSISignal    + 执行层 = best（不动）

  → 只换 Entry，其他完全相同
  → 回答的问题："RSI 信号 vs EMA 信号，谁的择时更好？"

  如果 RSI 赢了 → 进入第二步
  如果 RSI 输了 → RSI 信号不如 EMA，可以尝试融合或放弃

═══════════════════════════════════════════════
  第二步：为胜出的信号重新优化执行层
═══════════════════════════════════════════════

  锁定 Entry = RSISignalEntry
  重新跑 4 阶段实验：
    Stage 1: 为 RSI 信号找最优 Tiers
    Stage 3: 为 RSI 信号找最优 Position
    Stage 4: 为 RSI 信号找最优 TakeProfit

  → 回答的问题："RSI 信号 + 什么样的执行最强？"

═══════════════════════════════════════════════
  最终对比：两个完整策略的 PK
═══════════════════════════════════════════════

  best_old = NDayConfirm + 最优执行A（已有）
  best_new = RSISignal   + 最优执行B（新调出来的）

  → 在 5 个环境下对比 Sharpe / 最大回撤 / 年化收益率
  → 这才是真正的"策略级"比较
  → 赢了就升级为新 Baseline
```

**为什么要分两步？**

- 第一步的目的是**快速筛选**：如果信号本身就不行，不值得花时间调执行层
- 第二步的目的是**充分发挥**：好信号配上好执行，才能展现真正实力
- 如果直接跳到第二步（信号和执行一起调），变量太多，分不清到底是信号的功劳还是执行的功劳

## 8. 信号层与执行层的独立优化矩阵

把所有组合列出来，可以看清全貌：

```
                    ┌─────────────────────────────────────────┐
                    │           执行层（怎么买）                │
                    ├──────────┬──────────┬──────────┬────────┤

                    │ ...      │ ...      │ ...      │ ...    │
  ┌─────────┬──────┼──────────┴──────────┴──────────┴────────┤
  │ 信号层  │Entry │                                          │
  │(何时买) │      │  每种 Entry × 每种执行组合 = 一个完整策略   │
  │         ├──────┤                                          │
  │         │无条件 │  无条件+执行A  无条件+执行B  无条件+执行C  │
  │         │EMA   │  EMA+执行A    EMA+执行B    EMA+执行C     │
  │         │RSI   │  RSI+执行A    RSI+执行B    RSI+执行C     │
  │         │融合   │  融合+执行A   融合+执行B    融合+执行C    │
  └─────────┴──────┴─────────────────────────────────────────┘

  理论上要测试所有组合，但实际上用分阶段锁定的方法大幅减少搜索空间。
```

## 9. 总结

| 概念 | 你需要记住的 |
|------|------------|
| 信号 vs 执行 | 策略 = 信号（何时买）+ 执行（怎么买），两者独立优化 |
| 公平比较信号 | 只换 Entry 模块，其他保持不变 → 比较信号质量 |
| 换信号要重新调执行 | 不同信号节奏不同，最优执行参数也不同 |
| 两步走 | 先比信号（快速筛选）→ 再调执行（充分发挥） |
| 多环境测试 | 不能只看一个时间段，要 5 个环境综合评判 |
| Baseline 迭代 | 建立 Baseline → 挑战者 PK → 赢了就升级 |
| 防止过拟合 | 多环境 + 参数鲁棒性 + 样本外测试 + 参数越少越好 |
| 最重要的指标 | Sharpe Ratio（收益/风险平衡）和最大回撤（最坏情况） |
| 实验框架已支持 | 往 configs.py 的候选列表加新模块，重跑即可 |
