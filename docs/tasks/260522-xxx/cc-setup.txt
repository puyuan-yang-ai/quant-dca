Background
This guide describes how to run Claude Code using AMD’s LLM Gateway (you must use this at AMD). Big thanks to Conor Donohue for the original steps.

You must have an LLM API Gateway Key, or request one through llm.amd.com.

Instructions
1. Install Claude Code
macOS, Linux, WSL:



curl -fsSL https://claude.ai/install.sh | bash -s stable
Windows PowerShell:



& ([scriptblock]::Create((irm https://claude.ai/install.ps1))) stable
Native Windows installs require Git for Windows.

2. Add claude to your PATH
If claude --version already works, skip this step.

bash / zsh (~/.bashrc or ~/.zshrc):



export PATH="$HOME/.local/bin:$PATH"
csh / tcsh (~/.cshrc):



setenv PATH "$HOME/.local/bin:$PATH"
Windows PowerShell (one-time, persistent):



[Environment]::SetEnvironmentVariable("PATH", "$env:USERPROFILE\.local\bin;$env:PATH", "User")
3. Create your settings file
Linux / Mac path: ~/.claude/settings.json  ·  Windows path: %USERPROFILE%\.claude\settings.json

Replace PASTE YOUR ACTUAL KEY INSIDE QUOTES with the LLM Gateway key from llm.amd.com.

FAQ
Q: I see “Select login method:” when I start Claude Code
Add the following to ~/.claude.json (Linux/Mac) or %USERPROFILE%\.claude.json (Windows). This is the file ~/.claude.json at the root of your home directory — not ~/.claude/.claude.json inside the .claude folder.



{
  "customApiKeyResponses": { "approved": ["dummy"], "rejected": [] }
}
This skips the “Trust API Key” prompt on first launch. You’ll still get the one-time theme-selection question, then Claude Code will start normally.

apiKeyHelper, hasCompletedOnboarding, and CLAUDE_CONFIG_DIR are sometimes suggested for this — they work in some scenarios but break when you use --setting-sources project or relocate your config. Use customApiKeyResponses unless you need CLAUDE_CONFIG_DIR for its real purpose (relocating the entire config dir, e.g. when /home is full).

Thanks to Christian DeAngelis for the cleaner guidance here.

Q: My requests time out on long agent runs or slow links
Claude Code’s default API timeout is 10 minutes. Raise it in env:



"API_TIMEOUT_MS": "1200000",
"CLAUDE_CODE_MAX_RETRIES": "20"
Q: TLS errors against llm-api.amd.com (“self-signed certificate”, “unable to verify the first certificate”, SELF_SIGNED_CERT_IN_CHAIN, CERT_HAS_EXPIRED)
The Node.js runtime Claude Code uses doesn’t read the OS trust store, so even on a managed AMD workstation you can hit these errors. Fix is two parts: (1) make sure the AMD root CA is trusted by your OS, then (2) point Claude Code at it via NODE_EXTRA_CA_CERTS.

These are the same steps used for GitHub Copilot — refer there for the canonical version.

Step 1: Download the AMD root certificate
Pick one source:

AMD_CA.crt (Confluence attachment)

AMD Corporate Root CA 2032.crt (Confluence attachment)

Internal AMD PKI server: http://pki.amd.com/CertEnroll/

Step 2: Install it system-wide
RHEL / CentOS / Fedora:



sudo cp AMD_CA.crt /etc/pki/ca-trust/source/anchors/
sudo update-ca-trust
Debian / Ubuntu:



sudo cp AMD_CA.crt /usr/local/share/ca-certificates/
sudo update-ca-certificates
If curl https://llm-api.amd.com/Anthropic previously returned SSL certificate problem: self signed certificate in certificate chain and now returns an HTTP response (any status), the cert is trusted.

If you have an expired AMD root cert lingering, find and remove .crt / .crt.puppet files in /usr/local/share/ca-certificates/ first, then re-run sudo update-ca-certificates.
