# 任务：Swing Low 波段底部可视化 & Oracle 改造

## 背景

当前 Oracle 极值的计算方式是"从全期间 N 个交易日中挑最便宜的 N 天取均价"，等于全局价格排序取底部。这不合理——即使先知也不会只在全局最低点买入，而是应该在**每个下跌波段的底部**都买入。

## 目标

### 第一阶段：可视化确认

1. 实现 Swing Low（摆动低点）算法，检测 SPY 价格的局部波段底部
2. 在交互式图表（`show_chart.sh`）中标注检测到的 swing low 点
3. 对比 N=5 和 N=10 两组参数的检测效果，评估哪个更适合定义"波段底部"

### 第二阶段：最小跌幅过滤 + Oracle 改造（待第一阶段确认后）

4. 加入**最小跌幅过滤**：要求从前一个局部高点到 swing low 的跌幅 > X%，排除横盘区间的微小波动被误识为"底部"
   - 需要先检测 swing high（局部高点），计算到 swing low 的跌幅
   - 跌幅阈值 X 待定（候选：3%、5%、7%），可视化后确定
5. 用过滤后的 swing low 波段底部均价替代现有 Oracle 的"N 天最低均价"
6. 重新计算所有策略的 Oracle 极值和极值利用率，更新 ground-truth.md

## Swing Low 算法定义

**定义**：第 i 天是 swing low（窗口 N），当且仅当 `close[i]` 严格小于左右各 N 天的所有收盘价。

```
对于第 i 天：
  close[i] < close[i-N], close[i-N+1], ..., close[i-1]  （左边 N 天）
  close[i] < close[i+1], close[i+2], ..., close[i+N]    （右边 N 天）
```

- 使用 **close**（收盘价）而非 low，与 DCA 回测的买入价口径统一
- N=5 → 前后各 1 周，检测较小波段的底部（数量多）
- N=10 → 前后各 2 周，只留较大波段的底部（数量少）

## 图表要求

- 市场环境：`all`（2022-01 ~ 2025-06），但 swing low 作为永久图表功能，所有环境可用
- 在 K 线主图上标注 swing low：橙色圆点 = 保留，灰色 × = 被过滤
- 去掉 VIX 子图（保留 K 线 + RSI + Breadth 三图）
- 去掉 DCA 买入/卖出箭头标记（本次只看 swing low）

## 结论

### 第一阶段

- **N=10 胜出**：22 个底部，比 N=5（50 个）更精准，过滤掉了大量小波动噪声
- **最小跌幅 3%**：过滤后保留 17 个。5% 对 SPY 偏高（如 2023-08-17 跌 4.7% 被误滤），3% 更合适

### 第二阶段

- **统一 Oracle 基准**：所有策略共用同一个 Oracle 极值（+15.35%），不再随买入次数变化
- **只取低于期间均价的 swing low**（10 个），排除牛市高位回调
- VIX AND NDay5 极值利用率 78.8%，为日线最优
