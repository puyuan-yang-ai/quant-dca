# 心智模型：这套每日推理系统到底是怎么运转的

> 用途：给"过几个月回来复盘"的自己看。不讲代码细节，只讲**整个系统的运转逻辑和几个关键认知**。
> 配套：同目录 `01-开发计划.md`（4 个脚本各干啥）、`02-Mac-mini-部署文档.md`（照着敲）。

## 一句话概括

把一个"已经训练好的模型文件"放到家里的 Mac mini 上，让 Mac mini 每天早上自动：拉最新行情 → 跑模型算个概率 → 写一份报告 → 把结果推送到你手机。整个过程不需要你守着。

## 最重要的一个认知：训练 和 推理 是两件事

这是整个设计的地基，想明白这个，后面全通。

| | 训练（Training） | 推理（Inference / 预测） |
| --- | --- | --- |
| 在哪做 | 开发机（你现在这台 Linux） | Mac mini |
| 多久做一次 | 偶尔（模型要更新时才做） | 每天 |
| 重不重 | 重（吃几十年历史数据算半天） | 轻（几秒钟） |
| 产物 | 一个**模型文件**（`models/spy_nday5_v3.ubj`，约 140KB） | 一份**当天的预测报告** |

**比喻**：训练像"考驾照"——费劲、偶尔做一次、做完拿到一张驾照（模型文件）。推理像"每天开车上班"——拿着驾照，轻松、天天做。Mac mini 只负责"开车"，不负责"考驾照"。

所以 Mac mini 上**永远不会跑训练**，它只是拿着你考好的"驾照"每天开车。模型要升级时，你在开发机上重新"考个新驾照"，再把新文件同步过去就行。

## 三个阶段的全局流程

```
┌─ 阶段一：开发机（一次性，偶尔重复）──────────────┐
│  写好脚本 + 训练出模型文件                          │
│         ↓                                          │
│  git add 全部（脚本 + 模型 + 历史数据）            │
│         ↓                                          │
│  git push 到 GitHub                                │
└───────────────────────────────────────────────────┘
                    ↓ （代码和模型通过 GitHub 当中转站）
┌─ 阶段二：Mac mini（一次性配置）────────────────┐
│  git clone（把整个项目拉下来）                      │
│         ↓                                          │
│  重建 Python 环境（venv + pip install）★必须      │
│         ↓                                          │
│  填配置（.env 里写 Telegram 的密钥）              │
│         ↓                                          │
│  手动跑一次，确认能拉数据、能推送                  │
│         ↓                                          │
│  装 launchd 定时器（设个每天 08:00 的闹钟）       │
└───────────────────────────────────────────────────┘
                    ↓
┌─ 阶段三：之后（全自动，你不用管）──────────────┐
│  每天 08:00 launchd 把脚本叫醒                      │
│   → 拉数据 → 推理 → 出报告 → 推送手机 → 退出      │
└───────────────────────────────────────────────────┘
```

## 五个容易理解错的关键点（认知纠偏）

### 1. 不需要"常驻进程"，只需要"定时任务"
一开始可能会想"是不是要起一个一直运行的后台程序？"——**不需要**。
- 常驻进程 = 7×24 一直开着的服务（比如网站后端），适合需要随时响应的场景。
- 你的需求是"每天跑一次"，属于批处理，用定时任务即可。
- 起常驻进程反而是坏处：它 99% 时间在睡觉空占内存，崩了你还不知道。

### 2. launchd 是"闹钟"，不是"保姆"
launchd 是 macOS 自带的定时器。准确理解它的行为：
- 到了 08:00，它把脚本**叫起来**；脚本跑完几秒钟**自己退出**；launchd 就不管了，直到明天 08:00 再叫一次。
- 中间**没有任何东西常驻**。这跟"常驻进程"正好相反。
- 选 launchd 不选 cron 的原因：Mac 睡眠时，cron 错过的任务不补，launchd 会在唤醒后补跑。

### 3. 跨平台：`.venv` 不能直接搬过去
- 开发机是 Linux x86，Mac mini 是 ARM（Apple Silicon），两者的 Python 虚拟环境**不通用**。
- 所以 `.venv/` 文件夹**不进 git**，Mac mini 上必须**重新 `pip install` 一遍**。
- 这一步不是"改个配置"那么轻，是要重新装 xgboost 等一堆库（pip 会自动下 Mac 版的）。

### 4. "每日最新数据"靠 Mac mini 自己联网拉
- 报告要"最新"，前提是 Mac mini 每天能联网从 Yahoo Finance 拉到当天数据。
- 如果哪天拉不到（断网/被墙），整条链路第一步就卡住。
- 所以脚本必须把"拉数据失败"当回事：重试几次，还失败就推送告警告诉你"今天没跑成"。

### 5. 模型是"弱信号"，报告是"研究观察"不是"交易指令"
- 这个模型样本外 AUC-ROC≈0.66（0.5 是瞎猜，1.0 完美），属于**略好于扔硬币**的弱信号。
- 每日报告的定位是**积累 track record、观察模型表现**，不是让你照着它真金白银买卖。
- 报告里会统一标注"仅供研究，非投资建议"；非信号日的概率还会额外提示"模型没见过这种情况，仅供参考"。

## 复盘时的自检问题

- 模型多久该重训一次？重训后怎么把新模型同步到 Mac mini？（答：开发机重训 → push → Mac mini `git pull`）
- 某天没收到推送，怎么排查？（答：看 Mac mini 上的 `logs/` 日志，多半是 fetch 失败或网络问题）
- 想改成每天跑两次 / 改时间？（答：改 `.plist` 里的 `StartCalendarInterval` 再重新装载）
