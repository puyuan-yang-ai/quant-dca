## 各文件关键设计

### ml/report.py
- 入口：`python -m ml.report [--input JSON] [--stdout]`
- 输入：`output/daily_prediction.json`（predict.py 产出）
- 输出：`reports/<as_of_date>.md`
- 核心函数 `build_markdown(r)`：把结果字典渲染成 Markdown，含核心结论、模型可靠性、feature importance 表（全部 21 个特征 + 当前值，按重要度降序）、数据新鲜度、风险提示。
- 设计点：
  - 非信号日额外插入"模型未训练此场景，仅供参考"提示。
  - 数据新鲜度逐源对比 `as_of_date`，落后的标 ⚠️。
  - 与推理解耦——改报告样式不动 predict.py。

### ml/notify.py
- 入口：`python -m ml.notify [--json JSON | --text TEXT] [--dry-run]`
- 配置读取 `_load_env()`：从 `.env` 读 `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` / `TELEGRAM_PROXY`，**环境变量优先于 .env**。
- 核心函数：
  - `build_summary(r)`：从 JSON 构造精简纯文本摘要（避免 Markdown 转义麻烦）。
  - `send_telegram(text, cfg, dry_run)`：调 Telegram sendMessage；dry-run 只打印。
- 设计点：
  - **dry-run 模式**：无密钥也能验证消息格式（测试/部署前自检）。
  - **缺密钥优雅失败**：打印清晰错误并 `exit 1`，供 run_daily.sh 判断。
  - **支持 --text**：run_daily.sh 失败告警复用此模式，不依赖 JSON。
  - **可选代理**：网络受限时 `TELEGRAM_PROXY` 走代理。

### scripts/run_daily.sh
- 入口：`bash scripts/run_daily.sh`（launchd 调用 / 手动验证）
- 流程：检查 venv → 等网络 → 拉数据 → 推理 → 报告 → 推送
- 设计点（针对 launchd/Mac 环境的坑）：
  - `PROJECT_ROOT` 由脚本自身位置推导，无硬编码。
  - 显式补 `PATH`（含 `/opt/homebrew/bin`），因 launchd 环境变量近乎为空。
  - `wait_for_network()`：探测 Yahoo，最多 6 次、间隔递增（10/20/.../60 秒），解决"唤醒即跑网络未就绪"。
  - 拉数据失败自动重试一次。
  - 每个致命步骤失败：写日志 + `alert()` 推送告警 + 退出。
  - **推送失败不致命**（报告已生成），仅记日志，脚本仍正常结束。
  - 日志按日期落 `logs/daily_YYYYMMDD.log`。

### deploy/com.quant.daily.plist
- 放置：`~/Library/LaunchAgents/com.quant.daily.plist`
- `StartCalendarInterval` Hour=8 Minute=0（Mac 系统时区，即北京时间 08:00）。
- `RunAtLoad=false`（装载不立即跑）。
- `StandardOutPath/ErrorPath` → launchd 层日志（脚本另有详细日志）。
- **部署前必须替换 `__USER__`** 为实际 Mac 用户名（文件头注释已写明）。
