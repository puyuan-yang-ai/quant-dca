# 指标/策略评估 SOP(标准操作流程)

## 文档定位

本文档定义"**收到一个新指标/策略后,如何系统化判断是否值得进入 ML 特征池**"的标准流程。**面向不熟悉量化研究流程的读者**,所有概念都从零讲清楚。

适用场景:
- 写完一个新规则策略,想知道是否有价值
- 从 TradingView 看到一个指标,想知道是否值得移植
- 想给 ML 特征工程做"前置门控",避免把垃圾喂给模型

## 第一部分:为什么需要这个 SOP?

### 问题:没有 SOP 时的常见困境

新手在写策略/收集指标时,通常的工作流是:

```
写一个策略 → 跑回测 → 看图觉得"还行" → 上线 或者 弃用
              ↑
              凭直觉判断
```

这个流程有 4 个问题:

1. **直觉会偏向新策略**:刚写完的策略总觉得很好,容易"高估自己的发明"
2. **没有横向对比**:无法回答"指标 A 比指标 B 更值得用"这种问题
3. **决策记不住**:三个月后再看,忘了当初为什么砍掉某个指标
4. **重复劳动**:每次评估都从零开始,没有积累

### 解决方案:用 SOP 取代直觉

```
写一个策略 → 跑 SOP(自动) → 看 Accept / Reject 报告 → 决策
                ↑
                标准化、可重复、可追溯
```

**这是从"靠感觉做研究"到"靠流程做研究"的质变。** 机构里每个量化研究员都有自己的 SOP 脚本,几年迭代后会成为重要资产。

### SOP 的核心价值

| 价值 | 说明 |
|------|------|
| **去主观化** | 数字说话,不靠"我觉得" |
| **横向可比** | 所有指标用同一把尺子衡量 |
| **决策可追溯** | 每个 Accept/Reject 都有量化理由,可复查 |
| **加速研究** | 30 秒判断 vs 30 分钟手工分析 |
| **避免重复劳动** | 一次写好,长期复用 |

### ⭐ 关键认知:**SOP 是"噪声过滤器",不是"强度过滤器"**

这是新手最容易误解的一点。SOP **不会**因为信号单独胜率/Sharpe 低就把它砍掉,**它砍的是"假信号"**(不稳定、不可解释、纯噪声、冗余):

| 筛选类型 | 标准 | SOP 做不做? |
|---------|------|----------|
| **强度筛** | 这个信号单独胜率/Sharpe 高吗? | ❌ **不做**(ML 能利用弱但稳定的信号) |
| **噪声筛** | 这个信号稳定吗?可解释吗?正交吗? | ✅ **做**(噪声会害死 ML) |

**举例对照**:

- 一个**胜率 45% 但稳定 + 显著 + 正交**的信号 → SOP 判 **ACCEPT** ✅(反向信号也是信号,ML 能用)
- 一个**胜率 65% 但只在某段历史显著**的信号 → SOP 判 **REJECT** ❌(历史巧合会害死模型)

**这背后的数学基础**(详见 `ml-execution-details-faq.md` Part 4):
- ML 通过"特征互补"利用弱信号,所以**强度门槛可以低**
- 但 ML 无法处理噪声/不稳定/冗余,所以**噪声门槛必须严**

**实操含义**:
- 不要因为 "Hit Rate 只有 53%" 就砍信号——只要通过 SOP 5 门就保留
- 不要因为 "Hit Rate 高达 65%" 就直接保留——要看是否稳定(SOP 门 2)

## 第二部分:基础知识(看懂 SOP 前必须知道)

### 关键概念扫盲

#### 1. GT(Ground Truth,真值标签)

回答"某一天是否真的是买点"的标准答案。**手工标注不可行**(主观、模糊、不可扩展),所以用**公式化标签**自动生成,如:

> 第 i 天向后看 N 天,如果期间最高价相对当前收盘价涨幅 > 阈值 → 标 1(是买点);否则 → 标 0

详见 `ml-gt-labeling-plan.md`。

#### 2. 前瞻收益(Forward Return)

第 i 天买入,持有 N 天后的收益率。SOP 用它来衡量"信号触发后未来发生了什么"。

#### 3. t-statistic(t 统计量)

衡量"信号触发后的平均收益,是否显著高于全样本平均收益"的统计量。**核心特性:它同时考虑"效应大小"和"样本量"**,防止"只有 1 个超准信号"的稀疏策略胜出。

公式:`t = (信号平均收益 - 基线平均收益) / (标准差 / √n)`

经验门槛:`|t| > 2` 算统计显著,`|t| > 3` 算高度显著。

#### 4. IC(Information Coefficient,信息系数)

指标值与未来收益的相关性(Spearman 秩相关)。量化行业的标准信号评估指标。

经验门槛(日线数据):
- IC > 0.05 优秀
- IC > 0.02 可用
- IC > 0.005 弱信号(对独立策略不够,但对 ML 特征够)

#### 5. Hit Rate(方向准确率)

信号触发后,未来 N 天涨/跌方向预测正确的比例。

经验门槛:
- > 53% 在金融数据中已经很好(信噪比极低)
- 顶级量化基金的实际 Hit Rate 也就 51~55%
- 不要期待 70%+,那大概率是过拟合或 lookahead bias

### 关键洞察:独立策略 vs ML 特征,标准完全不同

**这是最容易被新手忽略的关键认知**:

| 维度 | 独立策略门槛 | ML 特征门槛 |
|------|-----------|-----------|
| t-statistic | ≥ 2 | ≥ 1 |
| IC | ≥ 0.02 | **≥ 0.005**(放宽 4 倍) |
| Hit Rate | ≥ 53% | 无硬门槛 |
| 稳定性 | 必须 | **必须**(不放宽) |
| 正交性 | 不强求 | **必须**(更严格) |
| 数量约束 | 无 | **特征数 ≤ √n** |

**为什么 ML 特征的强度门槛可以放松?**

举例:两个 Hit Rate = 53% 的弱因子,**如果它们犯错的模式不同**(即独立),组合后:

```
组合 Hit Rate ≈ 1 - (1-0.53) × (1-0.53) ≈ 78%
```

从 53% 跃升到 78%。这就是**多样性定理**:一群"水平差不多但风格不同"的弱信号,组合后比单个强信号更准。**ML 的价值正是在于"利用因子互补性",所以单个弱也能用,关键是"是否与已有特征互补"**。

**但有 4 条铁律不可放松**:
1. 因子必须**稳定**(否则学到的是历史巧合)
2. 因子必须**正交**(否则只是噪声放大)
3. 因子数必须**≤ √n**(否则过拟合)
4. 因子必须**可解释**(否则故障无法诊断)

## 第三部分:SOP 的 5 道筛选门

把以上知识落地为可执行的 5 步流程,每步独立判定,不通过则拒绝。

### 门 1:可解释性(秒级)

**问题**:你能用一句话讲清楚这个指标在测什么吗?

- 能 → 进入门 2
- 不能 → **REJECT**(可解释性是 ML 特征的硬约束)

**说明**:个人量化场景下,无法解释的特征即使训练表现好,你也不敢实盘执行,而且故障时无法诊断。

### 门 2:稳定性(分钟级)

**问题**:把数据按时间切分,因子的预测方向在不同时段是否一致?

具体做法:
- 按 12 个月滚动窗口切分数据
- 每个窗口分别计算 IC
- 统计 "IC > 0" 的窗口比例(或 "IC < 0" 的)
- 取较大值,称为 **sign agreement**

判定:
- sign agreement ≥ 70% → 进入门 3
- sign agreement < 70% → **REJECT**(不稳定,拟合历史巧合)

**说明**:金融市场会发生 regime shift(市场结构变化),不稳定的因子在新环境会失效。这条比"信号强度"更重要。

### 门 3:统计显著性(分钟级)

**问题**:信号触发后的收益,是否显著优于基线?

计算:
- t-statistic(主要)
- IC(辅助)

判定:
- `|t| ≥ 1.5` OR `|IC| ≥ 0.01` → 进入门 4
- 都不达标 → **REJECT**(信噪比太差,组合也救不回来)

**说明**:这里的门槛(t ≥ 1.5)比独立策略(t ≥ 2)宽松,因为 ML 能利用弱信号组合。

### 门 4:正交性(分钟级)

**问题**:这个因子的信息,是否已经被已入池特征覆盖?

计算:
- 与每个已入池特征的 Pearson 相关系数
- 取绝对值最大者 `max_corr`

判定:
- `max_corr < 0.7` → 进入门 5
- `max_corr ≥ 0.7` → **REJECT**(已有特征已覆盖,冗余只增加噪声)

**说明**:相关性高的特征会让 SHAP/feature importance 分析失真,也增加过拟合风险。

### 门 5:边际贡献(后期验证)

**问题**:加入这个特征后,ML 模型整体性能(AUC-PR)是否提升?

具体做法:
- 在已有特征集上 walk-forward CV 训练 baseline → 得 5 fold AUC-PR
- 加入新特征重训 → 得 5 fold AUC-PR
- 计算 fold 级差异:`fold_diff = mean(new) - mean(old)`,`std_diff = std(diffs)`

判定(AND 关系):
- `mean(fold_diff) ≥ 0.005` AND `mean(fold_diff) > 2 × std(fold_diff)` → **FINAL ACCEPT**
- 否则 → **REJECT**(无显著边际贡献)

**说明**:
- 评估必须基于 Walk-Forward CV(详见 FAQ Part 8),而不是单一 val 评估
- 双重门槛防止"平均看起来提升,实际只是随机波动"
- 这步只能在 Master Roadmap 阶段 3(baseline 建立后)做
- 前期可暂时跳过,通过门 4 即标记为 "PENDING"

### 决策汇总表

| 阶段 | 通过门数 | 状态 |
|------|---------|------|
| 门 1~4 全过 | 4/5 | **PENDING**(候选入池,等门 5 验证) |
| 门 5 也过 | 5/5 | **ACCEPT**(正式入池) |
| 任何门不过 | < 4 | **REJECT** + 拒绝理由 |

## 第四部分:实施方案

### 阶段 A:文档与示例(本文档完成,无需代码)

明确 SOP 的逻辑和判定标准。本文档即交付物。

### 阶段 B:MVP 代码实现(Master Roadmap 阶段 1 副产品)

**位置**:`ml/evaluate_indicator.py`

**核心接口**:

```python
def evaluate_indicator(
    indicator_series,        # 指标值(连续或 0/1)
    price_data,              # K 线数据(用于计算前瞻收益)
    existing_features=None,  # 已入池特征字典,用于正交性检查
    horizon=10,              # 前瞻周期(天)
    threshold=0.03,          # GT 标签阈值
):
    """
    返回:
      verdict: "ACCEPT" / "PENDING" / "REJECT"
      report: dict 包含 t_stat / ic / hit_rate / stability / max_corr
      reason: 字符串,通过/拒绝的具体理由
    """
```

**输出示例**:

```
═══════════════════════════════════════
指标评估报告:RSI_divergence_v2
═══════════════════════════════════════
门 1 可解释性 : ✅ PASS (人工确认)
门 2 稳定性   : ✅ PASS (sign agreement 78%)
门 3 显著性   : ✅ PASS (t = 2.34, IC = 0.024)
门 4 正交性   : ✅ PASS (max corr 0.45 with VIX)
门 5 边际贡献 : ⏸  待验证(需在阶段 3 后跑)
───────────────────────────────────────
VERDICT: PENDING(候选入池,等基线建立后验证边际贡献)
═══════════════════════════════════════
```

### 阶段 C:接入工作流

每次新增策略或指标:

1. 实现指标计算逻辑(返回 series)
2. 调用 `evaluate_indicator()`
3. 看 verdict 决策:
   - ACCEPT/PENDING → 加入 `ml/features.py` 的特征池
   - REJECT → 记录拒绝理由,归档

### 阶段 D:持续维护

- SOP 报告归档到 `docs/tasks/260516-xxx/sop-reports/`
- 季度回顾:已入池特征是否仍稳定?
- 重新跑 SOP,失效的特征移出

## 第六部分:常见误区(给新手的警示)

| 误区 | 正确认知 |
|------|---------|
| "Hit Rate 60% 才值得用" | 金融数据 53% 已经很好,顶级基金也就 51~55% |
| "回测 Sharpe 5+ 是好策略" | 大概率是 lookahead bias / 过拟合,真实策略 Sharpe 1~2 已优秀 |
| "因子越多越好" | 特征数必须 ≤ √n(1640 样本约 40 个,800 样本约 28 个) |
| "AUC 0.9 的模型很强" | 金融 ML 的 AUC 0.6 已经非常好,0.9 几乎肯定有数据泄漏 |
| "看图觉得不错就上" | 人眼会自动忽略反例,必须用统计指标 |
| "ML 能从垃圾数据里挖出金子" | 不能。垃圾进 → 垃圾出。SOP 就是过滤垃圾的门 |
| "量化只找微弱稳定的小机会,不存在大确定机会" | **两种范式都成立**,只是 ML 系统化策略只能捕捉前者,详见下方扩展说明 |

### 扩展说明:"小而频" vs "大而稀"两种范式

**ML 系统化择时的主流观点**:量化不是寻找"巨大确定性的机会",而是在巨大噪声中识别**微弱但稳定**的统计优势——这背后的数学是 `t = SNR × √n`,即用大样本量(n)弥补低信噪比(SNR)。

**但这种说法过于绝对**。实际市场中**两种机会都存在**:

| 范式 | 适用场景 | 频率 | 单次回报 | 谁能捕捉 |
|------|---------|------|---------|---------|
| **小而频的统计优势** | 系统化 / ML / 量化 | 高(每周/每月) | 小(1~5%) | ML 模型 ✅ |
| **大而稀的确定机会** | 主观 / 宏观 / 价投 | 低(每年几次) | 大(10~50%) | 人工判断 ✅ |

**为什么 ML 只能做"小而频"**?
- "大而稀"的机会(如 2020 COVID 底、2022 Q4 极端超卖)5 年才出现 2~3 次
- ML 训练样本不足,学不到稳定规律
- 即使学到,统计显著性也极差(`t = SNR × √n` 在 n 很小时 t 不够)

**实战配置建议**:**混合策略最优**——ML 处理日常 80% 的决策(小而频),保留 20% 的人工判断给极端事件(大而稀)。不要让"量化只找小机会"这个说法**否定你对市场大机会的判断力**——它只是说"ML 这个工具" 不适合捕捉大机会,而不是"大机会不存在"。

**对 SOP 的具体含义**:SOP 评估的是"能否进 ML 特征池",所以用"小而频"标准(t > 1.5, IC > 0.005 即可)。但**SOP 不评估"主观大机会判断"** ——那是另一条决策路径,不在本文档范围。
