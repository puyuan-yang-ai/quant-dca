# 通达信指标翻译（前 3 名）：Pine + Python 双版本

把 `指标.txt`（通达信 TDX 公式）里价值排序前 3 名的指标，各翻译成 **Pine Script 版**（TradingView 验证用）和 **Python 纯函数版**（验证通过后接入量化系统用）。

## 工作流（核心逻辑）

```
通达信公式  →  翻译  →  Pine 版在 TradingView 上肉眼验证有效性
                          │
                          ├─ 有效 → 启用同逻辑的 Python 版，接入 src/ 量化系统
                          └─ 无效 → 调阈值重验 / 放弃
```

两版**逻辑严格对齐**，所以 TradingView 上验证的就是 Python 跑的。

## 三个指标做了什么

| 指标 | 信号 | 翻译范围 / 丢弃部分 |
|------|------|----------|
| ④ 三重背离 | MACD/KDJ/RSI 各自的底背离、顶背离 + 三重共振 + 超卖买点 | 全翻译；丢弃可视化柱 |
| ⑤ OBV量能 v1 | OBV量能潮、量价同步QS、量均线、放量分级 FL1~4 | 丢弃“吸拉派落”（依赖外部指标 XLPL，无法移植） |
| ⑤ OBV量能 **v2 精简版** | **归一化量能潮(0-100) + 量价背离 + 天量③④** | 在 v1 基础上重构：去噪、归一化，**推荐用这版** |
| ① 买卖雷达 | 6日RSI 下穿85=卖点；多周期RSI超卖+AR人气低=买点 | 丢弃“主力吸货”分色柱（可视化、价值低） |

### 指标⑤ 为什么有 v2 精简版

v1（`ind5_obv.pine`）在 SPY 上信噪比差：量能潮是上亿量纲不可读、“量价同步QS”粉色背景
满屏（条件太宽=等于没信号）、①② 小级别量峰太频繁。v2（`ind5_obv_v2.pine`）重构为：

- **归一化到 0-100**，配 20/50/80 参考线，一眼读强弱；
- **删除 QS 粉条和 ①②**，只留两类高价值信号：
  - **量价背离**：价格创新高/新低但量能不配合 → 转折预警（用枢轴 pivot 比较）；
  - **天量 ③④**：近 120/250 日最大量 → 常对应恐慌底 / 出货顶。

实测（SPY 2024 至今）：底背离 3 次、顶背离 12 次、天量④ 2 次（精准命中 2025-04 暴跌放量）。

#### ⚠️ 背离信号有 pivLen 根的确认滞后（已修复 repaint）

枢轴(pivot)判定需要其右侧 pivLen(=5) 根数据，所以"某天是高/低点"要等它之后再走
5 根才能确认。**旧版曾把"顶背/底背"标签画回高/低点当天（offset=-pivLen），造成
"价格已跌几天、却在之前高点冒出顶背"的事后诸葛亮假象（repaint/前视偏差）。**

现版本已修复：背离信号标在**确认根**（高/低点 + 5 根），即真正可知、可下单那天。
代价是信号比高/低点**晚约 5 个交易日**，落在价格已启动之后。使用时须知：
- 它**不是精准抄顶摸底**，而是"5 天后确认前方形成了量价背离"的**趋势转弱信号**；
- 回测/接入只能用 `bull_div`/`bear_div`（确认根），**禁止**用 `*_at_pivot`（含未来信息）。

对比：**指标④ 三重背离、指标① 买卖雷达均无此问题**——它们基于 CROSS / 当根判定，
信号当天即触发，不需要未来数据，不重绘。

## ⚠️ 重要：Pine 代码必须「整体粘贴」，不要逐字符输入

Pine Script 是**缩进敏感**语言。实测发现：若在 TradingView Pine 编辑器里逐字符
输入（或被自动补全/自动缩进介入），多行函数体（`f(...) =>` 换行后的缩进块）
会出现**缩进逐级累加的雪崩**，导致大量编译错误。

应对措施（本仓库已采用）：
- 三个 `.pine` 里的自定义函数都改写成**单行函数**（`f(a,b) => 表达式`），不含多行缩进块。
- 使用时请**直接全选复制 `.pine` 文件内容，一次性 Ctrl+V 粘贴**进 Pine 编辑器，
  不要一行行手敲。粘贴后确认顶层语句都顶格、无意外缩进。

## 验证步骤（在 TradingView）

1. 打开 TradingView，加载 **SPY**（或 SMH）日线图。
2. 新建 Pine 指标，**整体粘贴**对应 `.pine` 文件内容（勿逐行手敲），添加到图表
   （`Add to chart` 需登录 TradingView 账号）。
3. 本地跑对数脚本，对照信号日期：

   ```bash
   cd docs/indicators/xxx
   python verify_signals.py SPY 2024-01-01
   ```

4. 逐点核对：Pine 图上标记的信号日期，应与脚本打印的日期一致（暖机段前若干根除外）。
5. **重点看信号是否“真有效”**：底背离是否落在真实底部、卖点是否落在阶段顶部。

## 两版的已知差异点（验证对不上时先查这里）

- **暖机误差**：EMA/RMA 的初始化（Python 用 SMA seed，TradingView 内部略不同），序列最前几十根数值会有差异，稳定后吻合。核对时忽略最前段。
- **经典指标算法**：MACD(12,26,9)、KDJ(9,3,3)、RSI（通达信 = RMA）两版都按标准算法，应吻合。
- **`BARSCOUNT(C)`（上市天数）**：Python/Pine 用 bar 序号近似（`i>50`）。SPY/SMH 数据够长，恒真，不影响。
- **背离的回溯逻辑**：照搬原公式“相邻两次金叉/死叉之间比较”，与常见的“摆动点背离”定义不同，这是**原指标的特定定义**，不是 bug。

## 阈值调参建议（重要）

原指标阈值是**针对 A 股个股**调的，直接用在美股 ETF 上会失真，实测发现：

- **指标④超买卖点（`A02>79`）在 SPY 上触发过于频繁**（高位连续报警）。ETF 波动小于个股，建议把超买阈值上调或改用相对分位。
- **指标①买点雷达（7日RSI<20 且 13日RSI<25）在 SPY 上几乎不触发**——ETF 很少有个股级别的深度超卖。建议放宽到 30/35 量级再观察。
- 这些阈值都集中在各 `.py` / `.pine` 的 `compute` / 顶部参数处，调参后两版要同步改。

## 接入量化系统（验证通过后）

当前 Python 版是**独立纯函数模块**，不依赖也不污染 `src/`。验证某指标有效后：

1. 把对应计算函数合入 `src/indicators/__init__.py`（注意复用已有的 `calc_ema`/`calc_rsi`）。
2. 在 `src/modules/entry/` 写一个 Entry 类包装其买入信号。
3. 按 CLAUDE.md 规则，用标准化执行层做信号比较（`FixedTiers(drops=())` + `FixedPyramid(market_shares=1)` + `NoTakeProfit()`）。
