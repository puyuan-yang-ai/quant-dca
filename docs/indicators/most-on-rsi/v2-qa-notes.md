# MOST on RSI v2 — 设计推演 Q&A 笔记

本文档记录 v2 设计过程中遇到的疑问、踩过的坑、以及最终的解决思路。方便事后复盘。

---

## Q1：为什么 MOST 的 BUY/SELL 信号不好用？

**现象**：MOST 标记的 BUY/SELL 点离实际顶底很远，信号出来时行情已经走了一大段。

**原因**：MOST 信号有三层滞后叠加：

```
价格拐点 → (滞后1) → RSI(14)拐点 → (滞后2) → RSI均线(VAR5)拐点 → (滞后3) → MOST翻转
                                                                          ↑
                                                              需要均线移动 9% 幅度
```

每一层都是平滑/延迟，三层叠加后信号严重滞后。

**结论**：MOST 适合做趋势跟踪的止损线（它的本职工作），但不适合做买卖点信号。v2 中完全去掉 MOST。

---

## Q2：为什么不用 RSI 直接穿越 RSI 均线作为信号？

**直觉**：去掉 MOST 后，最简单的替代是看 RSI 上穿/下穿 RSI 均线。

**问题**：RSI 是一条"毛躁"的锯齿线，均线是平滑线。一条毛躁的线穿越一条平滑的线，在震荡区间会频繁来回穿越，假信号泛滥。

```
RSI（锯齿状）：    ╱╲╱╲╱╲╱╲╱╲
                       ↕↕↕ 频繁穿越
RSI 均线（平滑）：  ─────────────
```

**但是**：配合 RSI < 40 / > 60 的门槛过滤后，这个问题大幅缓解。在底部/顶部区域，RSI 与快均线的交叉是有方向性的回归信号，不是震荡噪音。所以 v2 最终采用了 RSI 穿越快均线(EMA5) + 门槛过滤的方案。

---

## Q3：为什么从双均线交叉改回了 RSI 穿越快均线？

**背景**：早期 v2 设计用了快慢双均线交叉（EMA5 上穿 EMA14），类似 MACD 的思路。

**问题**：两条都是平滑线，它们的交叉仍然有明显延迟。RSI 可能已经从底部反弹了好几根 K 线，快慢均线才交叉。

**改进**：改用 RSI（原始未平滑信号）穿越快均线(EMA5)。这样是一条"快线"穿越一条"平滑线"，交叉响应速度最快。

```
v1:   RSI → VAR均线 → MOST → 信号        （三层平滑，最慢）
早期v2: RSI → 快EMA5 → 慢EMA14 → 信号     （两层平滑，较慢）
最终v2: RSI 直接穿越 EMA5 → 信号           （一层平滑，最快）
```

## Q4：RSI < 40 的门槛检查为什么要用滚动窗口？

**最初的 bug**：v2 第一版代码用 `rsi < buyGate` 做门槛检查，即检查"此刻"的 RSI 是否 < 40。

**问题**：交叉事件（RSI 上穿快均线）触发时，RSI 正在从底部回升，往往已经回到 40 以上了。门槛检查不通过，信号被过滤掉。图表上看不到任何买入信号。

```
RSI:   22   25   28   32   36   40   43
                                ↑     ↑
                          RSI=40      RSI 上穿快均线
                          勉强通过     rsi=43 > 40, 门槛不通过!
```

**修复**：改用 `ta.lowest(rsi, N) < buyGate`，检查"最近 N 根内 RSI 是否曾低于 40"。这样即使交叉发生时 RSI 已经回到 43，只要近期曾到过 35，门槛就通过。

**教训**：凡是涉及"回顾近期是否满足条件"的逻辑，都应该用滚动窗口（`ta.lowest` / `ta.highest`），而不是检查单一时刻的值。

---

## Q5：极端检查（RSI < 30 加分）为什么窗口要比门槛检查更宽？

**现象**：RSI 上穿快均线时，门槛通过了（近 5 根内 RSI 曾 < 40），但极端加分没有触发（近 5 根内 RSI 未曾 < 30），即使看图表 RSI 明明到过 22。

**原因**：RSI 极端低点（< 30）往往发生在交叉之前 6-10 根 K 线的位置。`crossLookback=5` 的窗口太短，低点已经滑出窗口了。

```
bar:    T-8   T-7   T-6   T-5   T-4   T-3   T-2   T-1    T
RSI:     28    25    22    25    28    32    35    37    39
                     ↑                                   ↑
              极端低点 22                          RSI 上穿快均线
              在 T-6, 距离 T 有 6 根              ta.lowest(rsi, 5) 看 T-4~T
                                                  最低=28, 28<30? 不是!
```

**修复**：极端检查改用 `divLookback`（默认 10）作为窗口，比门槛检查的 `crossLookback`（默认 5）更宽。这样能捕获到更早出现的极端低点。

```
ta.lowest(rsi, 5)  → 看 T-4 到 T   → 可能漏掉极端低点
ta.lowest(rsi, 10) → 看 T-9 到 T   → 能捕获到 T-6 的 22
```

**门槛检查为什么不用加宽**：门槛是 RSI < 40，这个条件比较容易满足，RSI 在底部区域会在 40 以下停留较多 K 线，5 根窗口通常够用。而 RSI < 30 是极端条件，可能只出现在少数几根 K 线上，需要更宽的窗口。

## Q6：为什么 v1 的 pivot 背离检测有问题？最终为什么改成实时检测？

**这是 v2 设计过程中经历的最大架构演变。**

### v1 的 pivot 方案

v1 用 `ta.pivotlow(rsi, 5, 5)` 检测 RSI 低点，需要等右边 5 根 K 线都比它高才能"确认"这是一个低点。

### 遇到的三个连锁问题

**问题 1：5 根延迟 = 错过入场**

```
bar:      P     P+1   P+2   P+3   P+4   P+5
RSI:      22    25    28    32    36    38
          ↑                                ↑
     RSI 实际触底                     5根后才确认背离
     此时不知道是底部                  此时信号才出来
                                      但行情已经走了一大段
```

**问题 2：Bull/Bear 标签是"作弊"**

为了让标签看起来"准"，用 `offset=-5` 把标签画回 5 根前的 pivot 位置。看起来像是在底部就预判到了，但实际上是 5 根后才知道的。在实盘中，回溯标记对交易决策毫无帮助——你不能穿越时光回到 5 天前去买入。

**问题 3：时序错位**

交叉事件（RSI 上穿快均线）通常发生在 pivot 和确认之间。此时背离尚未确认，交叉事件查不到背离，导致无法升级。为此引入了复杂的"双向检查"机制来弥补。

### 根本反思

核心问题是：**等 5 根确认，是想确认"这是不是真的底部"**。但其实：

- 在实盘交易中，你永远无法确认当下是不是底部
- 背离的本质是"价格创新低但 RSI 没有创新低"——这个判断当下就能做
- 多等 5 根 K 线并不能真正确认底部，只是确认了"RSI 比低点高了 5 根"

### 最终方案：实时背离检测

**逻辑**：在 `divWindow`（默认 14）根内找到参考低点。如果当前价格比参考低点更低、但 RSI 比参考点时更高 → 看涨背离。零延迟，当下出信号。

```
v1 (pivot):  价格触底 → 等5根确认 → 出信号（已错过入场）
             ↓ 为了标签好看 → 回溯画标签（作弊）
             ↓ 交叉在确认前 → 看不到背离（时序错位）
             ↓ 解决时序错位 → 双向检查（复杂）

v2 (实时):   价格创新低 + RSI未新低 → 当下出信号（可即时行动）
             ↓ 无延迟 → 无需回溯标签
             ↓ 无时序错位 → 双向检查变简单
```

**参数从 5 个简化为 1 个**：`divWindow`（默认 14，与 RSI 周期一致）。

### 取舍

实时检测可能比 pivot 方案多一些假信号（没有"等 5 根确认"的过滤），但：
- 门槛系统（RSI < 40）已经过滤掉了大部分噪音
- 首次触发去重（`and not bullDivRaw[1]`）避免连续重复信号
- 最小间隔 2 根（`DIV_MIN_SEP = 2`）避免相邻 bar 噪音比较
- 及时性远比"少几个假信号"重要——错过一个真信号的代价远大于忽略一个假信号

## Q7：信号标签应该画在哪里？

**设计原则**：

> 所有交易信号标签都画在**当前 bar**（信息可知的时刻），表示"此刻可以行动"。

这个原则贯穿整个 v2 设计：

- 事件 1（RSI 下破 30）→ B 画在当前 bar
- 事件 2（RSI 上穿快均线）→ B/B+/B++ 画在当前 bar
- 事件 3（背离检测）→ B+/B++ 画在当前 bar

**绝不使用 offset 回溯标记交易信号**。回溯标记在实盘中等于欺骗自己。

中间版本曾经用 `offset=-lookbackRight` 把背离的 B+ 画到 pivot 位置，被否定了——因为那个时间点已经过去，无法行动。

---

## Q8：为什么 divWindow 默认值选 14？

**原因**：与 RSI 计算周期（14）一致。

- RSI(14) 本身就是对 14 根 K 线的平滑计算
- 在同样 14 根的窗口内比较价格和 RSI 的相对高低，维度匹配
- 日线上约 3 周，足够覆盖两次探底
- TradingView 社区主流背离指标多用 14

比 20（太宽，可能比较不相关的低点）和 10（太窄，可能漏掉间隔较远的探底）都更平衡。

## Q9：实时背离检测具体怎么工作？

### 核心逻辑

```
在最近 divWindow(14) 根 K 线中，找到价格最低的那根 bar（参考点）。
如果当前价格 < 参考点价格（价格创新低），
且当前 RSI > 参考点 RSI（RSI 没有创新低），
→ 看涨背离。
```

### 最小间隔

参考点至少在 2 根前（`DIV_MIN_SEP = 2`），避免相邻 bar 的微小波动被误判为背离。

### 去重

`bullDivAlert = bullDivRaw and not bullDivRaw[1]`

如果价格连续多根都满足"创新低且 RSI 未新低"，只在**第一根**触发信号。后续 bar 不重复。

### 与双向检查的配合

实时背离没有延迟，所以双向检查变得简单直接：

- **正向**（事件 2 查背离）：交叉时查 `divWindow`(14) 根内有没有背离 → 正常工作
- **反向**（事件 3 查交叉）：背离时查 `crossLookback`(5) 根内有没有交叉 → 正常工作

不再有"背离还没确认、交叉已经发生"的时序错位问题。

## Q10：为什么 B+ 和 B++ 比 B 还多？信号分布倒挂问题

### 现象

在 TradingView 上观察图表，发现信号分布严重倒挂：

- 预期：B 多 > B+ 少 > B++ 罕见
- 实际：B 少，B+ 和 B++ 反而很多

### 根因：背离检测缺少 RSI 水平约束

之前的背离条件只检查"价格更低 + RSI 更高"：

```pinescript
bullDivRaw = low < low[refBuyBack] and rsi > rsi[refBuyBack]
```

问题是：两个 RSI 都在 35-40 的点之间比较"谁更高"毫无意义。比如参考点 RSI=38，当前 RSI=40，价格更低——这不是真正的"卖压减弱"，只是正常波动。

但代码把它当成背离 → B+ 信号泛滥 → `recentBullDiv` 几乎常年为 true → 事件 2 的交叉也轻松拿到背离加分 → B++ 也泛滥。

### 修复：参考点 A 的 RSI 必须 ≤ 30

```pinescript
bullDivRaw = low < low[refBuyBack] and rsi > rsi[refBuyBack] and rsi[refBuyBack] <= extremeBuy
```

新增约束：参考点 A 的 RSI 必须处于极端超卖（≤ 30）。这确保背离比较的是"深度超卖时的卖压"vs"当前的卖压"，差异才有意义。

### 连锁效果

- 背离触发变少 → B+ 变少
- `recentBullDiv` 不再常年为 true → 事件 2 的背离加分变难拿 → B++ 变少
- 信号分布回归正常：B 多 > B+ 少 > B++ 罕见

### 教训

背离不仅要看"方向"（RSI 是否更高），还要看"水平"（参考点是否真的超卖）。没有水平约束的背离检测本质上只是在比较噪音。

---

## 总结：v2 设计中的核心教训

| 教训 | 具体表现 | 解决方案 |
|------|---------|---------|
| 条件检查要用滚动窗口 | 门槛 `rsi < 40` 在触发时刻已回升到 43 | 改用 `ta.lowest(rsi, N) < 40` |
| 不同检查需要不同窗口宽度 | 极端低点在 6-10 根前，5 根窗口漏掉 | 门槛用 `crossLookback`(5)，极端用 `divWindow`(14) |
| 延迟检测不如实时检测 | pivot 等 5 根确认 → 错过入场、回溯标签、时序错位 | 改为实时背离：价格新低+RSI未新低，零延迟 |
| 交易信号只能画在当前 bar | 回溯标记对实盘交易无用（等于作弊） | 所有 B/B+/B++ 画在当下可知的时刻 |
| 参数越少越好 | 5 个背离参数让用户困惑 | 合并为 1 个 `divWindow`(14) |
| 背离需要水平约束 | 无约束的背离检测把噪音当信号，导致 B+ 比 B 还多 | 参考点 RSI 必须 ≤ 30 才算有效背离 |
