## 专家决策框架

读取 orders.md 后，依次评估以下 4 个维度。每个维度是对基础 Vertical 的一次"低效诊断"。命中 0 个 → 不升级（基础 Vertical 已是最优）。命中 1+ 个 → 组合对应修复方案。

### 维度 1：时间对齐

> 基础 Vertical 的短腿到期日是否远晚于 thesis 关键日？

**低效的本质**：Vertical 的两腿同 DTE。当 thesis 在关键日兑现（价格到达短腿 strike）时，短腿仍有大量时间价值——这个时间价值是你的敌人，它让 spread 只能实现 50-70% max profit，即使价格完美到位。

**修复**：将短腿 DTE 对齐到 thesis 关键日。关键日当天短腿到期 → 时间价值归零 → 利润完整兑现。长腿保留原 DTE 作为 thesis 偏移的缓冲。这就是 Diagonal 的核心价值。

**判断标准**：如果 thesis 关键日到短腿到期日之间还有 ≥ 5 个交易日 → 时间对齐低效成立 → 建议 Diagonal。

### 维度 2：方向敞口

> thesis 是否存在"超预期突破"的合理可能（概率 ≥ 15%）？

**低效的本质**：Vertical 的短腿封死了上涨/下跌空间。如果 thesis 中有 scenario B 暗示价格可能远超基础目标（如突破性事件、FOMO 加速），短腿把这部分超额收益送给了市场。

**修复**：移除短腿（变为纯 Long Call/Put），或将短腿 strike 大幅外移以保留更多空间。代价是更高的 debit，通常需要搭配维度 3（Credit 补贴）来降低成本。

**判断标准**：如果 scenario_evolution 中存在"加速/延伸"类备选剧本且概率 ≥ 15% → 方向敞口低效可能成立。但需权衡：bounded target + 5 天持仓 → 通常不需要此维度。

### 维度 3：Credit 补贴

> thesis 中是否有一个明确的、概率极低被触及的关键位可以"靠着卖"？

**低效的本质**：orders.md 中有清晰的止损位/强支撑/强阻力，且基础 Vertical 没有利用这个位置收取 credit。这是"白白放弃"的安全 premium。

**修复**：在该关键位卖出一个反方向 Vertical（如看涨时在支撑位卖 Bull Put Spread），收取 credit 补贴主仓成本。关键：该 credit spread 的 DTE 应 ≤ 主仓短腿 DTE（让它更早归零，减少管理时间）。

**判断标准**：如果 orders.md 的止损位距离当前价 ≥ 0.8%，且该位置有 MMA 周期/技术面支撑 → Credit 补贴机会成立。

### 维度 4：事件杠杆

> thesis 中是否有一个 1-3 天内的高确信度催化剂？

**低效的本质**：主仓用 10+ DTE 的结构去捕捉一个 1-2 天的精确事件（如 Solar-Lunar 极值日、非农、CPI）。这意味着你在为 8 天的"无用"时间价值买单，杠杆率被稀释。

**修复**：在事件日前 1 天用极小仓位买入 Short DTE 单腿（到期日 = 事件日或次日）。这是"卫星仓"——成功则放大主仓收益 20-50%，失败则归零但金额极小。

**判断标准**：如果 orders.md 中引用了 Solar-Lunar 值 > 135* 或等效高确信催化剂，且事件日距今 ≤ 3 个交易日 → 事件杠杆机会成立。仓位硬性上限 = 主仓 max loss 的 15%。

## 推导流程

```
1. 读取 orders.md → 提取：方向、thesis 关键日、目标位、支撑/阻力、DTE、VIX
2. 逐一评估 4 维度 → 每个维度输出：命中(是/否) + 一句理由
3. 命中 0 个 → 结论：不升级，输出原因，结束
4. 命中 1+ 个 → 对每个命中维度选取修复积木 → 组合成升级方案
5. 检查组合后总腿数 ≤ 4，无裸卖，无反向 Diagonal
6. 风险自检（见下方）
7. 运行 fetch_spy_options.py 获取真实报价
8. 输出最终方案
```

## 风险自检

升级方案组装完成后，回答以下 3 个问题。任一为否 → 降级方案复杂度或放弃升级。

1. **裸卖检查**：每条 Sell 腿是否都有同类型、同到期或更远到期的 Buy 腿覆盖？
2. **亏损可承受**：升级后总最大亏损（所有腿 worst case 同时发生）占期权预算的百分比是多少？专家自行判断是否超出合理范围（参考：单笔交易 max loss 通常不超过期权预算的 35-40%）。
3. **可执行性**：老虎证券能否以 1-2 笔组合限价单完成全部建仓？是否需要 leg-in（逐腿建仓）？如果必须 leg-in，滑点风险是否可接受？
